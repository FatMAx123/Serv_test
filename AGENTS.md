## 1. Неизменяемые архитектурные инварианты (Core Invariants)

### 1.1. Нативный C++ SIMD боевой движок и Spatial Grid (`project_steam_native.node`)
- **Исходники:** `native/src/combat_engine.h`, `native/src/spatial_grid.h`, `native/src/main.cpp`, сборка: `binding.gyp`.
- **Правило:** C++ модуль компилируется с оптимизациями `-O3 -mavx2` и ускоряет боевые расчеты и коллизии в 35–40 раз.
- **Запрещено:**
  - Удалять директорию `native/` или файл `binding.gyp`.
  - Отключать нативную загрузку или заменять расчеты на чистый JavaScript в продакшене.
  - Исключать `native` из скрипта деплоя `scripts/deploy-vps.js`.

### 1.2. C++ Zero-GC Сетевой транспорт (`uWebSockets.js` v20.70.0)
- **Файлы:** `server/net-transport.js`, `ecosystem.config.js`.
- **Параметры окружения:** `NET_ENGINE: 'uws'`, `STRICT_UWS: '1'`.
- **Правило:** В продакшене сервер работает ИСКЛЮЧИТЕЛЬНО на uWebSockets.js (Zero-GC, нативный C++ Pub/Sub, поддержка 3000–5000+ CCU).
- **Запрещено:**
  - Откатывать сетевой транспорт на устаревший `ws` (Node.js pure JS WebSocket).
  - Устанавливать `STRICT_UWS=0` или `NET_ENGINE=ws` для обхода ошибок компиляции uWS.
  - Предлагать пользователю или в логах "Set NET_ENGINE=ws and STRICT_UWS=0 to bypass". При отсутствии бинарника uWS сервер обязан завершаться с фатальной ошибкой (fail-fast), требуя сборки uWS.

### 1.3. Разгрузка через Worker Threads (vCPU 2 Offload)
- **Файлы:** `server/workers/persistence-client.js`, `server/workers/persistence-worker.js`.
- **Правило:** Сохранение состояния персонажей, сериализация БД и тяжелое I/O вынесены в отдельный поток worker threads, гарантируя нулевое влияние на лаг тика основного игрового цикла.
- **Запрещено:** Возвращать синхронное или асинхронное дисковое I/O в главный поток `server.js`.

### 1.4. Оптимизации синтетических ботов (Bot Throttling Invariants)
- **Файлы:** `server/server.js`.
- **Критические проверки, которые НЕЛЬЗЯ удалять ни при каких обстоятельствах:**
  1. `broadcastMoveVecStart` и `broadcastMoveVecStop`:
     ```javascript
     if (isOriginBot) return; // Боты перемещаются дискретно, спам векторов запрещен!
     ```
  2. `clampSpeed` (проверка высоты геодаты):
     ```javascript
     // Трассировка GEO.standY выполняется ТОЛЬКО для реальных игроков:
     if (!p.yid || !isSyntheticBot(p.yid)) {
       // GEO.standY...
     }
     ```
     *Вызов `GEO.standY` на каждый микро-шаг сотен ботов генерирует 50 000+ рейкастов в секунду и намертво вешает CPU.*
  3. `ensureNearbyMobs`:
     ```javascript
     if (p.yid && isSyntheticBot(p.yid)) return; // Боты НЕ спавнят мобов!
     ```
  4. `recomputeAOI`:
     Лимиты видимости: для ботов 24 (soft) / 32 (hard), для игроков 128 (soft) / 160 (hard).

## 3. Регламент деплоя на боевой VPS (Production VPS Protocol)

1. **Деплой осуществляется только скриптом:** `node scripts/deploy-vps.js`.
2. **Скрипт обязан:**
   - Переносить полный код сервера: `server/`, `shared/`, `data/`, `ecosystem.config.js`, `package.json`.
   - Переносить C++ нативные исходники: `native/` и `binding.gyp`.
   - На сервере выполнять установку зависимостей и сборку нативного аддона: `npm install --production && npx node-gyp rebuild`.
   - Перезапускать процессы через PM2: `pm2 restart ecosystem.config.js --env production`.
   - Проверять статус процессов PM2 (`online`, CPU 0%, память < 200MB).
3. **После деплоя обязательна проверка:**
   - `node tests/run.js` (все модульные тесты должны проходить 100%).
   - Проверка логов `/var/log/project-steam/out.log`: подтверждение `uWebSockets.js C++ Zero-GC [ACTIVE]` и `C++ AVX2 SIMD АКТИВЕН`.
