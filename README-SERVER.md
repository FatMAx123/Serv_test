# Сервер Project Steam — запуск и эксплуатация

> 📚 **Интерактивная Многоагентная Документация Сервера:**  
> [**Открыть Главный Портал Документации (server_docs/index.html)**](file:///d:/games/yandex/лайнэйдж/project-steam1/server_docs/index.html) — 8 глав: архитектура кластера, бинарный транспорт, Spatial Grid, боевой движок, 16 хэндлеров, персистентность, античит и оптимизация 5000 CCU.

Сервер = авторитетный «ведущий» MMO. Клиент шлёт только намерения, сервер решает всё (античит).  
Поддерживает как одиночный режим (разработка/тесты), так и многоядерный кластерный режим (до 5 000 CCU).

## 1. Системные требования
- **Node.js:** v18+ LTS (проверка в терминале: `node -v`).
- **RAM:** от 2 ГБ для локальной разработки, от 8 ГБ для high-load продакшена.
- **ОС:** Windows, Linux, macOS.

## 3. Режимы запуска сервера

### 3.1. Одиночный процесс (Dev / Standalone)

```bash
npm start
```

Сервер запускается с оптимизированными флагами V8 (`--max-semi-space-size=128 --max-old-space-size=4096`) на локальном порту `8080`.  
Проверка живого сервера в браузере:
* `http://93.77.168.135` — статус сервера: `Project Steam MMO server is running.`
* `http://93.77.168.135/metrics` — оперативные метрики тика, памяти и очередей
* `http://93.77.168.135/healthz` — healthcheck тикрейта для балансировщиков

> ⚠️ **Сетевой периметр в продакшене:** Игроки и браузерный клиент **никогда не подключаются к порту 8080 напрямую**. Прямое подключение к 8080 медленное (Event Loop нагружается статикой) и блокируется в браузере (Mixed Content в HTTPS Яндекс Игр). В продакшене публичные порты — строго **80 (HTTP / WS)** и **443 (HTTPS / WSS)** через Nginx Reverse Proxy, а порт 8080 изолирован на `127.0.0.1`. Локальное клиентское меню и отладка запускаются на порту **3000** (`npm run menu` -> `http://localhost:3000/menu.html?server=93.77.168.135`).

### 3.2. Кластерный режим (High-Load 4 воркера, до 5 000 CCU)

```bash
npm run start:cluster
```

Поднимает мастер-процесс `server/cluster-manager.js` и 4 специализированных воркера по зонам карты:
1. **Town Worker** — деревня и торговый хаб (высокая концентрация игроков, магазины, склады, чат).
2. **East Worker** — восточные тренировочные поля и равнины.
3. **West Worker** — западная свалка и карьеры автоматонов.
4. **North Worker** — северные холмы и руины.

Воркеры обмениваются событиями через межпроцессный IPC Hub, а сокетный I/O изолирован по процессам.

## 4. Проверка WebSocket и Сетевой Протокол

Клиент подключается к живому серверу `ws://93.77.168.135` (или через WSS `wss://...`) и отправляет пакет авторизации:

```json
{
  "t": "login",
  "data": "...base64url-данные-игрока...",
  "signature": ""
}
```

### 4.1. Двусторонний Heartbeat и Защита от Разрывов (1005/1006/4001)
- **Строгий порядок рукопожатия (Защита от `4001 login first`):** Самым первым исходящим пакетом при открытии сокета (`ws.onopen`) гарантированно отправляется `loginMsg`. Пакеты пинга `t: 'ping'` блокируются до завершения авторизации (`status === 'online'`), исключая сброс сокета сервером при старте.
- **Клиентский Heartbeat (`tickHeartbeat`):** После авторизации клиент отправляет `{ t: 'ping', time: Date.now() }` каждые 8 секунд; сервер отвечает `{ t: 'pong' }`. Клиент также немедленно отвечает `{ t: 'pong' }` на серверные пинги.
- **Интеграция с фоновым тикером:** Вызов `this.net.tickHeartbeat()` встроен в Web Worker тикер (`_onBackgroundTick`) и в основной кадр рендера (`_frame`). Сокет не засыпает и не сбрасывается по 120-секундному таймауту (`4001 session timeout`) даже при длительном нахождении в фоновой вкладке.
- **Обновление Активности (`lastPong`):** Сервер обновляет таймштамп активности сессии `s.lastPong = Date.now()` при получении **любого входящего пакета** от игрока (движение, клик, скилл, чат, пинг/понг). Это исключает ложные срабатывания таймера неактивности во время игры.
- **Стабильность RFC 6455 (Фикс 1005/1006):**
  - Код `1006` по спецификации WebSocket запрещен для отправки в кадре закрытия (`Close Frame`). В кластерном прокси `GatewaySocketProxy` и в `cluster-manager.js` любые коды `1005`/`1006` автоматически транслируются в валидный код `4001`.
  - В C++ движке `uWebSockets.js` отключен принудительный разрыв неактивных соединений (`idleTimeout: 0`), а таймаут сессии на сервере увеличен до 120 секунд с мягким закрытием через `ws.close(4001, 'session timeout')`.
  - Функция `verifyWsClient` поддерживает динамическую проверку `same-origin` (когда заголовок `Origin` совпадает с `Host` запроса), а также прямой белый список IP сервера (`93.77.168.135`).

### 4.2. Фоновая Симуляция Браузера ("Фейковая Пауза")
- Браузеры (Chrome, Yandex, Safari) при сворачивании окна или смене вкладки принудительно замораживают `requestAnimationFrame`.
- Для непрерывного игрового процесса в клиенте (`client/js/main.js`) внедрен независимый **Web Worker Background Ticker** (~25 FPS).
- При переключении вкладки:
  - **Для браузера:** WebGL рендеринг (`renderer.render`) отключается (0% GPU нагрузки), аудио глушится (`GameAudio.setPageHidden(true)`).
  - **Для игры:** действия персонажа (бег к цели, автоатака, каст скиллов, сбор лута, сетевой обмен с сервером) **не останавливаются**.
  - При возврате во вкладку часы сбрасываются без скачка дельты, и рендер мгновенно возобновляется.

### 4.3. Синхронизация Геометрии Мира и Оверрайдов Ландшафта (PLAN 4.6)
- **Изоляция инструментов редактора:** Согласно PLAN 4.6 тяжелый код `editor.js` не загружается обычным игрокам (грузится только GM-аккаунтам). Для обычных игроков работает легковесный модуль `WorldContent` (`client/js/world-content.js`).
- **Сквозная поддержка оверрайдов в `WorldContent`:** Метод `findMeshForProp()` полноценно сопоставляет ключевые объекты сцены:
  - `mountains_root` / `MountainsRoot` — корень горного массива `window.Mountains.root`;
  - `volcano` / `VolcanoMesh` — 3-Tier LOD меш вулкана `window.Volcano.lod` с автоматическим обновлением `worldCenter` для корректного переключения уровней детализации;
  - `water` / `water_root` — водная гладь `window.WaterSystem.root`.
- **Эталонные координаты по умолчанию:** В `mountains.js` и `volcano.js` по умолчанию заложены эталонные координаты сцены (`mountainsRoot`: `x: -101.5, y: -356.54, z: -860.5`, scale `2.04`; `volcano`: `x: 1214.5, y: -18.97, z: -1655.0`, scale `479.24`), что гарантирует идеальное совпадение ландшафта у новых игроков и у GM-аккаунтов без летающих полигонов и козырьков.

## 5. Эксплуатация в Продакшене (VPS / PM2 / Nginx)

- **Конфигурация PM2 (`ecosystem.config.js`):**
  - Обязательно `watch: false`. Режим `watch: true` в продакшене запрещен, так как синхронизация файлов через SFTP/Git вызывает каскадные рестарты процессов и обрыв игроков.
  - Перезагрузка без простоя: `pm2 reload ecosystem.config.js`.
- **Конфигурация Nginx:**
  - `proxy_read_timeout 86400s;` и `proxy_send_timeout 86400s;` — исключают разрыв долгоживущих WebSocket сессий.
  - `worker_connections 16384; worker_rlimit_nofile 65535; multi_accept on; use epoll;`.

## 7. Мониторинг `/metrics`

Эндпоинт `GET /metrics` возвращает JSON с метриками реального времени:
* `online` — текущее количество активных WebSocket-подключений.
* `tickMs` — время выполнения последнего игрового тика (норма: < 15 мс).
* `tickAvgMs` — скользящее среднее времени тика.
* `eventLoopLagMs` — задержка планировщика Node.js Event Loop.
* `dirtyProfiles` — текущий размер очереди отложенной записи профилей Write-Behind.
* `packetsOut` / `bytesOut` — исходящий трафик и сетевая статистика.
* `rssMb` / `heapUsedMb` — потребление оперативной памяти процессом.
