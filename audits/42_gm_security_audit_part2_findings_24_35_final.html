1. Исполнительное Резюме

В рамках второй части внешнего аудита безопасности игрового сервера GM был проведен детальный построчный анализ пунктов 24–35. Все выявленные векторы атак были сопоставлены с архитектурными инвариантами проекта Project Steam: Origins. Каждый дефект был оперативно устранен на уровне исходного кода без компромиссов для производительности или отката сетевого/боевого стека (Zero Rollback Policy).

Сетевой и Клиентский Стек P1 Высокий

Внедрена жесткая фильтрация целевых игровых серверов в клиенте через server-hosts.js. Ликвидирован вектор фишинговых ссылок ?server=attacker.com с очисткой несанкционированных записей из localStorage.

Целостность Данных и CWH P1 Высокий

Устранено окно гонки и дюпа предметов в клановом хранилище при внезапном падении сервера. Списание CWH гарантированно фиксируется перед обновлением сумки персонажа. Файлы кланов пишутся атомарно через .tmp.

Нативный C++ SIMD Стек P2 Средний

Проведен аудит буферов Float32Array и Int32Array в main.cpp. Добавлена N-API валидация длин массивов и безопасное клампирование координат в spatial_grid.h.

3. Клиентская Защита и Фишинг (п. 24)

Ликвидация Host Spoofing / WebSocket Hijacking P1 Высокий

Ранее клиент допускал чтение хоста из произвольных параметров строки запроса ?server=evil.com и сохранял их в постоянное хранилище браузера. В случае перехода по фишинговой ссылке злоумышленник мог перехватить сессию игрока.

Создан единый защищенный модуль client/js/server-hosts.js с белым списком разрешенных адресов. Все клиентские скрипты (config.js, char-select.js, menu-page.js, game.html) теперь обращаются к PS_SERVER.sanitizeHost(). При обнаружении чужого хоста он немедленно стирается.
+ const ALLOWED_HOSTS = new Set(['93.77.168.135', '93.77.168.135.sslip.io']); + function sanitizeHost(candidate) { + if (isAllowedHost(candidate)) return candidate; + return '93.77.168.135'; // Безопасный возврат к официальному серверу + }

4. Аудит, Логирование и Приватность (п. 25)

Защита от Disk Exhaustion DoS P2 Средний

Внедрен жесткий рейт-лимит для эндпоинтов /api/mod/* и /api/admin/*: не более 30 запросов в минуту с одного IP. Запись аудита неуспешных попыток авторизации ограничена 5 строками в минуту.

Гарантия Валидности JSON P2 Средний

Замена опасного метода JSON.stringify().slice(0, 2000) на предварительную санитизацию объекта sanitizeLogRow(rec). Каждая строка в audit_actions.jsonl на 100% валидна и распарсиваема.

Приватность Личных Сообщений /tell P3 Низкий

Текст личных сообщений игроков больше не сохраняется в журналы чата в открытом виде. Логируются только метаданные длины { len: text.length }, что исключает утечку конфиденциальной переписки.

5. Атомарность CWH и Защита от Дюпа (п. 26)

Инвариант Порядка Сохранения при doClanWhTake P1 Высокий

Если игрок забирал ценное снаряжение из кланового хранилища, ранее сначала сохранялся профиль игрока, а затем обновлялось хранилище клана. При аварийном завершении сервера между этими двумя записями вещь дублировалась.

Порядок сохранения строго реверсирован: в первую очередь вызывается await Clans.save(c) (списание из клана), и только после успешной фиксации вызывается await saveProfileNow(p). Также внедрена запись файлов кланов через временные файлы .tmp и атомарный rename.

6. Нативный C++ SIMD и Буферы (п. 27, 35)

Валидация TypedArray Буферов P2 Средний

В методах GridBulkInsert и GridQueryRadius в нативном модуле C++ добавлена строгая проверка типов буферов N-API и валидация минимальной длины length >= count * 8, исключая Segfault при поврежденных массивах.

Клампирование Координат Сетки P2 Средний

В spatial_grid.h функция getCellIndex теперь клампирует координаты к допустимым индексам ячеек вместо возврата -1, предотвращая потерю игроков и мобов за границами карты.

7. Игровые Механики и Безопасность (п. 29–34)

Разделение Пати-Лута на Дропах Игроков (п. 30) P2 Средний

При ручном сбросе предмета на землю флаг playerDrop: true гарантирует, что вещь попадет поднявшему игроку напрямую без случайной передачи союзникам по группе через правила random или turn.

Защита от Prototype Pollution в SK.get (п. 31) P2 Средний

Запросы к навыкам с ключами __proto__, constructor или свойствам прототипа возвращают null через строгую фильтрацию и hasOwnProperty.

Канонический Потолок Валюты (п. 32) P3 Низкий

В процедуру giveCurrency внедрено ограничение максимальной суммы адены: MAX_CURRENCY_CAP = 2 147 483 647 (канон Lineage 2 C1), исключающее переполнение счетчика.

Криптостойкий CSPRNG Заточки (п. 34) P2 Средний

Вероятность заточки оружия и доспехов переведена с Math.random() на криптографически стойкий crypto.randomInt(), исключающий прогнозирование исходов энчанта.
