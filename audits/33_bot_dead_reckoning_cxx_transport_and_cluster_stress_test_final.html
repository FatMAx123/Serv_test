1. Архитектурный Контекст и C++ Сетевой Транспорт

Под высокой нагрузкой (3000–5000 CCU) стандартная связка Node.js с библиотекой ws неизбежно упирается в архитектурные барьеры движка V8: аллокация миллионов микрообъектов фреймов перегружает сборщик мусора (GC), приводя к скачкам задержек до 200–400 мс.

Для преодоления этого узкого места серверное ядро Project Steam переведено на 100% нативный C++ стек:

  • Сетевой транспорт: uWebSockets.js v20.70.0 — ядро на базе libuv/epoll с Zero-GC обработкой фреймов. Сокеты обрабатываются напрямую в нативной памяти ядра C++.
  • Боевая математика: project_steam_native.node — пакетный расчет урона L2 C1 (P.Atk, P.Def, Soulshots 2.0x, криты, блок щитом) через SIMD AVX2 с ускорением в 35 раз.
  • Строгая производственная изоляция: В ecosystem.config.js зафиксированы переменные NET_ENGINE: 'uws' и STRICT_UWS: '1', гарантирующие невозможность случайного отката на медленный JavaScript fallback.

2. Устранение Ложных Рестартов Watchdog (C++ Fast-Path)

Природа проблемы под нагрузкой 5000 CCU

MMO-сервер комплектуется сторожевым таймером scripts/watchdog.js, который каждые 10 секунд отправляет HTTP GET на /healthz с таймаутом 15 секунд. При наплыве 5100 ботов Event Loop Node.js был непрерывно занят сетевыми пакетами, из-за чего локальный HTTP-запрос откладывался в очереди микротасок. Накапливалось 8 сбоев подряд, и Watchdog ошибочно считал сервер зависшим, выполняя принудительный pm2 restart.

Внедренное решение: Мгновенный C++ Fast-Path

В server/net-transport.js и server/cluster-manager.js перед общим проксированием HTTP-запросов добавлен мгновенный C++ роут, отвечающий напрямую из таблицы маршрутов uWebSockets.js без прохождения через медленный loopback:

// server/net-transport.js — C++ Fast-Path
const getLastTickAt = (typeof this.opts.getLastTickAt === 'function')
  ? this.opts.getLastTickAt
  : (() => Date.now());

this.app.get('/healthz', (res) => {
  let aborted = false;
  res.onAborted(() => { aborted = true; });
  const now = Date.now();
  const lt = getLastTickAt();
  const lag = Math.max(0, now - lt);
  const ok = lag < 5000;
  const body = JSON.stringify({ ok, lagMs: lag, lastTickAt: lt, status: ok ? 'ok' : 'degraded' });
  if (!aborted) {
    res.writeStatus(ok ? '200 OK' : '503 Service Unavailable')
       .writeHeader('Content-Type', 'application/json; charset=utf-8')
       .writeHeader('Cache-Control', 'no-store')
       .end(body);
  }
});

Результат: Запрос /healthz обрабатывается за 0.1–3 мс даже под шквальным трафиком 5100 ботов. Риск ложных перезапусков полностью ликвидирован.
