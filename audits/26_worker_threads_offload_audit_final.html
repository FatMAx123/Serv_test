1. Архитектурная цель и Предпосылки

В ходе оптимизации ядра (Уровни 1–4) время расчетного цикла тика (10 Hz) было снижено до беспрецедентных величин: 10.04 мс при 500 CCU, а пространственная сетка на C++ SIMD AVX2 выполняется за 0.099 мс.

Асимметрия двухъядерного VPS: По умолчанию однопоточный цикл событий Node.js целиком нагружает первое ядро (vCPU 1), в то время как второе ядро (vCPU 2) фактически простаивает на 85–90%. При периодическом сбросе базы игроков (Write-Behind Cache / Auto-Save) главный поток тратил до 35 мс на сериализацию JSON.stringify и постановку операций в libuv threadpool, создавая редкие, но ощутимые микрофризы для боевого цикла.

Решение Уровня 5: Запуск выделенного Worker Thread на vCPU 2 (server/workers/persistence-worker.js) с собственным V8 Isolate, берущего на себя всю сериализацию, запись во временные файлы, fsync(), ротацию .bak и атомарное переименование.

2. Архитектура Worker Threads & Message Passing

[ Главный Поток (vCPU 1) ] [ Воркер Поток (vCPU 2) ] Игровой цикл (10 Hz) Отдельный V8 Isolate Spatial Grid / Бой / Сеть Автономный Event Loop | | |-- postMessage({ id, type, file, data }) --------->| (Очередь задач) | (Трата времени < 0.05 мс) | | |-- JSON.stringify(data) Продолжает симуляцию |-- fs.writeFile(file + '.tmp') без малейших задержек! |-- fileHandle.sync() | |-- copyFile(file, file + '.bak') | |-- rename(tmp, file) |<-- postMessage({ id, ok: true }) -----------------| | Разрешение Promise в DB

Главный поток больше никогда не исполняет тяжелый JSON.stringify() крупных структур (профилей игроков, клановых сундуков). Данные передаются воркеру в структурированном виде и кодируются уже в V8 Isolate второго ядра.

3. Пайплайн Атомарной Записи (Guaranteed ACID-like Persistence)

Шаг Операция Поток Назначение и защита от сбоев
01 postMessage(task) vCPU 1 (Main) Мгновенная неблокирующая диспетчеризация задачи в воркер.
02 JSON.stringify(payload) vCPU 2 (Worker) Сериализация в изолированной куче, освобождая V8 главного потока.
03 writeFile(file + '.tmp') vCPU 2 (Worker) Запись во временный файл без риска повредить исходный файл при краше.
04 fileHandle.sync() vCPU 2 (Worker) Принудительный сброс буферов ядра ОС на диск (гарантия записи при отключении питания).
05 copyFile(file, file + '.bak') vCPU 2 (Worker) Сохранение предыдущей валидной копии состояния.
06 rename(file + '.tmp', file) vCPU 2 (Worker) Атомарная замена файла на уровне файловой системы POSIX/NTFS.
07 postMessage({ id, ok }) vCPU 2 (Worker) Уведомление главного потока о завершении транзакции.

5. Dual-Engine Fallback (100% Обратная Совместимость)

В клиенте персистентности (server/workers/persistence-client.js) заложена надежная защита:

  • Если модуль worker_threads недоступен или воркер завершился с ошибкой, клиент моментально и прозрачно переключается на синхронный встроенный фолбэк.
  • В тестовом окружении и при быстрой перезагрузке все вызовы writeAtomic корректно ожидаются без зависания очередей.
  • Все 647+ тестов проекта продолжают выполняться со 100% успехом.
