1. Контекст и Модель Угроз (L3/L4/L7 Threat Model)

3. Детализация Архитектурных Решений Защиты

3.1. Защита от Исчерпания Соединений (VULN-DDOS-01)

В класс UwsServerTransport интегрирован реестр this.ipConnections = new Map(). Проверка количества подключений перенесена на стадию HTTP upgrade: если IP превысил порог MAX_CONNS_PER_IP (25 сокетов), сервер немедленно возвращает статус HTTP 429 Too Many Requests и закрывает рукопожатие. Это предотвращает выделение памяти в куче V8.

3.2. Pre-JSON Фильтрация Пакетов (VULN-DDOS-02)

Входящие сообщения проходят через локальный счетчик ws._msgRate до вызова JSON.parse(raw): 

// server/server.js: pre-JSON rate limiting
if (!ws._msgRate || now > ws._msgRate.resetAt) {
  ws._msgRate = { count: 1, resetAt: now + 1000 };
} else {
  ws._msgRate.count++;
  if (ws._msgRate.count > 60) {
    ws.close(4008, 'rate limit exceeded'); // Терминирование атакующего
    return;
  } else if (ws._msgRate.count > 40) {
    return; // Мгновенный отброс без синхронного JSON.parse
  }
}

3.3. Семафор и Очередь Вычислений PBKDF2 (VULN-DDOS-05)

Для защиты 8 рабочих потоков libuv от исчерпания тяжелыми 25 000 раундами HMAC-SHA512 внедрена очередь queueKdfJob с максимальным параллелизмом MAX_CONCURRENT_KDF = 3: 

// server/account-keys.js: KDF concurrency queue
function queueKdfJob(fn) {
  return new Promise((resolve, reject) => {
    if (activeKdfJobs >= MAX_CONCURRENT_KDF && kdfQueue.length >= MAX_KDF_QUEUE) {
      const err = new Error('kdf concurrency limit exceeded');
      err.code = 'ERR_KDF_BUSY';
      return reject(err);
    }
    kdfQueue.push({ fn, resolve, reject });
    runNextKdfJob();
  });
}

limit_req_zone $binary_remote_addr zone=mmo_auth_limit:10m rate=3r/s;

# Защита от флуда в блоке /api/auth/

    limit_req zone=mmo_auth_limit burst=5 nodelay;
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
