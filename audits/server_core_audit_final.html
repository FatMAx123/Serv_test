🌐 3. Архитектура Кластера и Шардинг
4 WORKERS • SEAMLESS HANDOFF

Для обеспечения масштабируемости до 3000+ одновременных игроков мир острова Круна разделен на 4 географических шарда, управляемых независимыми рабочими процессами (Zone Workers) под координацией Master Gateway.

Механика Бесшовного Handoff без разрыва сокета ▼

Когда персонаж смещается за пределы зоны текущего воркера с учетом буфера HYSTERESIS = 15м:

  1. Воркер $A$ формирует снимок сущности profileOf(p) с сохранением pid, yid, connId, баффов, DoT, инвентаря и группы.
  2. Закрываются временные сессии: отменяется трейд (peer_gone) и прерывается дуэль (zone_change).
  3. Воркер $A$ передает IPC-сообщение MSG_HANDOFF в Master Gateway.
  4. Master Gateway атомарно обновляет маппинг workerIdByConnId.set(connId, targetWorkerId).
  5. Воркер $B$ принимает снапшот, создает прокси-сокет GatewaySocketProxy, инстанциирует Player и добавляет его в свой SpatialGrid.
  6. Результат: Игрок не испытывает разрыва соединения, сетевой сокет не пересоздается.
Приграничная Репликация Призраков (Border Ghosts) ▼

Для устранения эффекта «исчезновения игроков на границе процессов» реализована подсистема Border Ghosts:

  • В полосе шириной 90 м вдоль границы зон (isNearBorder) воркер каждые 200 мс передает список игроков соседям через MSG_BORDER_GHOSTS.
  • Соседний воркер вставляет призраков в локальную сетку SpatialGrid с флагом isGhost: true.
  • Призраки реплицируют координаты, экипировку и анимации бега, но их физика и боевые расчеты остаются на домашнем воркере.

🗺️ 5. Spatial Hash Grid и Алгоритмы AOI
ZERO-GC • < 1 МКС

В модуле server/spatial-grid.js реализована 2D-сетка пространственного хеширования с упаковкой ключа в 32-битное целое число.

Упаковка 32-битного ключа ячейки и выборка 3x3 spatial-grid.js
function _key(cx, cz) { // Упаковка координат ячейки в 32-битный unsigned int (Zero-GC, никаких строк "x_z") return (((cx + 32768) & 0xFFFF) << 16) | ((cz + 32768) & 0xFFFF); } // При выборке опрашиваются максимум 9 смежных ячеек (диапазон 108 метров) for (let dx = -1; dx <= 1; dx++) { for (let dz = -1; dz <= 1; dz++) { const cell = this.grid.get(_key(cx + dx, cz + dz)); if (cell) candidates.push(...cell); } }
Tiered Knownlist: Квантование частоты обновления по дистанции ▼

Для масштабирования на сотни сущностей в поле зрения применяется трехуровневое квантование:

  • Tier 1 (≤ 16 м или цель в таргете): 10 Hz (каждый тик). Плавный ближний бой без задержек.
  • Tier 2 (16–45 м): 5 Hz (каждый 2-й тик). Достаточно для плавной интерполяции перемещения.
  • Tier 3 (> 45 м): 2.5 Hz (каждый 4-й тик). Обновление дальнего горизонта с минимальной нагрузкой на процессор.

Срыв Каста Уроном (Cast Interrupt) ▼

При получении урона во время каста заклинания сервер проверяет шанс срыва:

P(interrupt) = min(0.85, (Damage * 1.2 / MaxHp) * (1 - (MEN - 20) / 100))

Высокий показатель MEN существенно снижает вероятность срыва заклинания. Прерывание сопровождается отменой каста и возвратом скилла на полный кулдаун.

🔒 9. Повторный Сквозной Аудит Безопасности и Устранение Уязвимостей
6/6 RESOLVED • 28 TESTS PASSED

Повторный построчный аудит всей кодовой базы сервера (server/, server/handlers/, server/http/, shared/) выявил и устранил 4 уязвимости безопасности и 2 логических расхождения с каноном L2 C1. Все исправления покрыты тестами в tests/security-vulnerabilities.test.js.

1. Account Takeover CRITICAL • CWE-306
Локализация: admin-api.js (L398), account-keys.js (L282)

Уязвимость: Ручка POST /api/auth/set-codeword принимала { yid, codeword } без подтверждения владения аккаунтом. Злоумышленник мог переписать пароль любого игрока или GM.

Решение: Внедрена валидация HMAC-SHA256 подписи Яндекса (AUTH.verifySignature), запрет на привязку не-local_ аккаунтов без подписи и обязательная проверка старого пароля (oldCodeword).

2. Arbitrary File Disclosure CRITICAL • CWE-200 / CWE-22
Локализация: cluster-manager.js (L442)

Уязвимость: В MasterGateway.serveStatic проверка пути разрешала отдачу любых файлов из REPO_ROOT (исходники server/, профили data/, .env, package.json).

Решение: Введены жесткие границы каталогов: доступ разрешен строго в client/, shared/ и terrain-paint-*.png. Попытки чтения server/, data/, .env возвращают 403 Forbidden.

3. 32MB WebSocket Frame DoS HIGH • CWE-400
Локализация: cluster-manager.js (L619)

Уязвимость: В MasterGateway.wss был захардкожен лимит фрейма 32 МБ даже в проде. Атакующий мог спамить 32 МБ фреймами, приводя к OOM кучи V8 и лавине IPC.

Решение: Лимит фрейма переведен на адаптивный режим: 64 КБ в проде (NODE_ENV=production) с поддержкой кастомного WS_MAX_PAYLOAD.

4. Socket Flood Rate Limiting MEDIUM • CWE-770
Локализация: cluster-manager.js (L642)

Уязвимость: Входящие пакеты от сокетов клиентов пересылались воркеру по IPC без ограничения частоты на уровне шлюза.

Решение: В _bindSocketEvents добавлен скользящий ограничитель (лимит 100 пакетов/с). При превышении сокет разрывается с кодом 4029 ('Rate limit exceeded').

5. Длительность PvP-флага LOGIC • CANON L2 C1
Локализация: duel-handler.js (L42)

Расхождение: Метод maybeFlagPvp выставлял флаг на 300 000 мс (5 минут), что блокировало телепорты, отдых и экипировку.

Решение: Длительность скорректирована до канонических 40 000 мс (40 секунд) согласно спецификации и разделу 10.1.

6. Карма PK (Убийство игроков) LOGIC • CANON L2 C1
Локализация: death-handler.js (L283)

Расхождение: При PK начислялось лишь фиксированных +100 кармы (смывалось за 1 моба).

Решение: Внедрена каноническая формула C1: базовая карма от 2400 до 7200 очков с масштабированием по числу совершенных PK.

РЕШЕНО (P0) Безопасность (CWE-200) Утечка исходного кода и .env через MasterGateway.serveStatic. Раскрытие приватных серверных файлов. Строгая изоляция: отдача файлов разрешена только из client/ и shared/ (плюс terrain-paint-*.png).
РЕШЕНО (P1) Безопасность (CWE-400) 32 МБ WebSocket maxPayload в MasterGateway. Риск DoS и переполнения памяти кучи V8. Адаптивный лимит: 64 КБ в продакшене (NODE_ENV=production) с поддержкой WS_MAX_PAYLOAD.
РЕШЕНО (P1) Безопасность (CWE-770) Отсутствие rate limiting на шлюзе перед IPC. Флуд пакетами по одному сокету. Внедрен скользящий лимитер 100 пакетов/с; при превышении сокет разрывается с кодом 4029.
РЕШЕНО (P1) Кластер Сброс соединений при сбое воркера (1012). Игроки упавшей зоны не отключаются. Внедрен 2000 мс буфер удержания сокетов restartingWorkerBuffers в MasterGateway, очередь пакетов packetBuffer и протокол MSG_SESSION_RESTORE для восстановления сессий без дисконнекта.
РЕШЕНО (P2) Shutdown Всплеск I/O при выключении (Promise.all 1000 сейвов). Пиковая нагрузка на диск при редеплое. Внедрен DB.saveBatch(batch) через UNNEST в PostgreSQL и пакетное сохранение Promise.all в FileBackend, интегрировано в shutdown, saveTimer и flushDirtyProfiles.
РЕШЕНО (P2) База Данных Ограничение масштабируемости файловой БД (>500 CCU). Задержки дискового I/O в продакшене. Внедрена строгая валидация assertProductionDatabase (fail-fast с кодом ERR_POSTGRES_REQUIRED), функциональные индексы JSONB и пул соединений с мониторингом в /healthz и /metrics.
РЕШЕНО (P2) Безопасность Риск dev-обхода в проде при отсутствии YANDEX_APP_SECRET. Несанкционированный вход и GM-доступ без подписи. Внедрена валидация assertProductionAuth (fail-fast с кодом ERR_AUTH_SECRET_MISSING), timing-safe проверка x-mod-secret в admin-api.js и изоляция AUTO_DEV_GM/p.dev/itest_ от продакшена.
P3 ИИ Мобов Отсутствие 3D Navmesh / A* вокруг П-образных стен. Моб может скользить вдоль забора. Внедрить 2D Navmesh Graph вокруг руин и замков в Фазе 2.
