1. Результаты Сверки со Сторонним Аудитом

Сторонний динамический аудит v3 представил точные факты: автор профаззил все 94 типа WS-сообщений, исследовал HTTP-роуты и снял дампы стека живого процесса. Все ключевые выводы подтвердились при детальном анализе исходного кода проекта:

P0-A. Вечный цикл AOI (move_stop) УСТРАНЕНО

Пакет move_stop без клампа границ записывал 1e308 в координаты. В spatial-grid.js цикл cx++ зацикливался из-за потери float-точности при $x > 2^{53}$.

P0-B. Crash HTTP на битом Cookie / URI УСТРАНЕНО

Вызов decodeURIComponent без try/catch в editor-guard.js и static-http.js бросал URIError, вызывая shutdown() всего процесса.

P1-A/B. local_* = GM (AccessLevel 100) УСТРАНЕНО

В gm-handler.js проверка local_* находилась вне условия продакшена. Любой гость мог получить права GM и ключ редактора editorKey.

2. P0-A: Защита SpatialGrid и move_stop от DoS

Механика бага: В стандарте IEEE 754 при числах масштаба 1e308 сложение с единицей возвращает то же самое число (1e308 + 1 === 1e308). В результате цикл for (let cx = minCx; cx <= maxCx; cx++) никогда не завершался.

Внедрённое решение (двухуровневая защита):

1. В server/server.js обработчик move_stop зажимает координаты строго в пределы игрового мира ($\pm 20000$):

case 'move_stop': {
  if (p.dead) return;
  const sx = (+msg.x != null && Number.isFinite(+msg.x)) ? +msg.x : p.x;
  const sz = (+msg.z != null && Number.isFinite(+msg.z)) ? +msg.z : p.z;
  if (sx < -20000 || sx > 20000 || sz < -20000 || sz > 20000) return;
  p.x = sx; p.z = sz;

2. В server/spatial-grid.js метод forEachCandidate снабжён защитой от переполнения и вечного цикла:

if (!Number.isFinite(x) || !Number.isFinite(z)) return;
if (!Number.isFinite(minCx) || !Number.isFinite(maxCx) || !Number.isFinite(minCz) || !Number.isFinite(maxCz)) return;
if ((maxCx - minCx) > 100 || (maxCz - minCz) > 100 || (maxCx - minCx) < 0 || (maxCz - minCz) < 0) return;
if (minCx < -2000 || maxCx > 2000 || minCz < -2000 || maxCz > 2000) return;

3. P0-B: Безопасный парсинг Cookie и URL

Невалидные последовательности процентного кодирования (например, %E0%A4%A) выбрасывали фатальный URIError. Теперь все точки входа защищены:

  • server/editor-guard.js: функция tokenFromCookie обёрнута в try/catch, возвращая пустую строку без вызова unhandled исключения.
  • server/static-http.js: функция resolveFile обёрнута в try/catch, отдавая null (безопасный 404/403).
  • server/server.js и cluster-manager.js: парсинг статики в serveStatic перехватывает URIError и возвращает HTTP 400 Bad Request.

4. P1-A/B: Изоляция local_* Гостевых Аккаунтов

В server/handlers/gm-handler.js проверка гостевого префикса перенесена строго внутрь блока NODE_ENV !== 'production':

function isGM(p) {
  if (!p || p.nonGm) return false;
  const lvl = (p.accessLevel | 0);
  if (lvl >= 50) return true;
  if (p.gm === true) return true;
  if (process.env.NODE_ENV !== 'production') {
    if (p.yid && String(p.yid).startsWith('local_')) return true;
    if (process.env.AUTO_DEV_GM === '1' && p.dev === true) return true;
    if (p.yid && String(p.yid).startsWith('itest_') && p.yid !== 'itest_regular' && !p.nonGm) return true;
  }

В продакшене гостевой аккаунт получает нулевой уровень доступа, не имеет прав на выполнение команд GM и не получает editorKey в welcome-пакете.

P1-C: Защита гостевых сессий (Guest Secret Token) и скрытие yid

Для предотвращения захвата гостевых аккаунтов и сброса сессий реализован механизм владения профилем:

  • Секретный ключ гостя: Браузер генерирует ps_guest_token в localStorage, сервер сохраняет guestTokenHash = SHA256(ps_guest_salt + token).
  • Защита онлайн-сессии от вытеснения: В doLogin перед вызовом detachPlayer сверяется хэш токена. Неавторизованный чужак отклоняется кодом 4003, а реальный игрок продолжает игру без дисконнекта.
  • Приватность yid: Из friendsPayload и friend_status удалено поле yid, исключая утечку идентификаторов аккаунтов.
