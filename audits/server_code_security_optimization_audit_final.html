2. BUG-SRV-03: Неработоспособность Зелий Нейтрализации Яда и Кровотечения

Дефект Логики в server/server.js (L6027-6040)

High Priority

В обработчике предмета (case 'use') проверка и фильтрация дебаффов осуществляется над массивом p.effects:

if (eff.curePoison) { if (Array.isArray(p.effects)) { p.effects = p.effects.filter(e => e && e.kind !== 'poison' && e.id !== 'poison'); pushEffects(p); send(p, { t: 'msg', text: 'Яд нейтрализован.' }); } }

Причина сбоя: В архитектуре серверной модели игрока все эффекты строго разделены на два массива: p.buffs и p.debuffs. Свойства p.effects не существует (оно всегда undefined). Условие Array.isArray(p.effects) никогда не выполняется. В результате расходник списывается, но яд и кровотечение остаются на игроке.

Корректное решение: Фильтровать массив p.debuffs:

if (eff.curePoison) { if (Array.isArray(p.debuffs)) { p.debuffs = p.debuffs.filter(e => e && e.kind !== 'poison' && e.id !== 'poison'); pushEffects(p); send(p, { t: 'msg', text: 'Яд нейтрализован.' }); } }

3. VULN-SRV-05: Эксплойт Каста Заклинаний и Одновременных Автоатак

Отсутствие срыва каста при атаке в server/server.js (L4965-5100)

High Priority

При начале каста заклинания вызовом doCastBegin в объекте игрока устанавливается запись p.casting. При перемещении более 1.2м или получении урона вызывается cancelPlayerCast.

Однако в обработчиках case 'attack' (атака мобов) и case 'attack_player' (PvP) проверка p.casting полностью отсутствовала. Игрок мог начать каст длительного умения (3-4 секунды) и во время этого каста непрерывно наносить удары автоатакой ближнего боя или лука, удваивая свой DPS.

if (p.casting) cancelPlayerCast(p, 'attack');

4. VULN-SRV-06: Модификация Предметов во Время Трейда и Лавки

Рассинхронизация состояния инвентаря в server/server.js

Medium Priority

В то время как действия drop_item и destroy_item защищены проверкой if (p.trade || p.store), обработчики case 'equip', case 'unequip', case 'craft' и case 'enchant' не проверяли занятость игрока торговлей.

Это позволяло во время подтверждения сделки изменять слоты экипировки или затачивать/крафтить предметы, вызывая потенциальные сбои и рассинхронизацию инвентаря.

5. BUG-SRV-04: Рассинхронизация Статов при Воскрешении в Город

Пропуск pushCombatStats и pushEffects в death-handler.js (L236-267)

Medium Priority

В функции revivePlayerToVillage(p) после смерти персонажа и сброса баффов/штрафов вызывается пересчет p.applyClassStats(), но пакеты combat_stats и effects не отправляются клиенту. Клиент оставался с устаревшими показателями атаки и защиты на экране до ручного переключения снаряжения.

6. PERF-SRV-03: Утечка Аллокаций и Нагрузка на GC в tickMobs

Создание замыканий sendDotDmg в mob-handler.js (L1094-1128)

Medium Priority

В основном цикле мобов для каждого моба с активными периодическими эффектами (DoT) каждые 100 мс создавалась анонимная функция sendDotDmg = (pl) => { ... }. Вынесение функции и переиспользование статического контекста устраняет миллионы лишних аллокаций в секунду при массовом бое.

7. VULN-SRV-07: Сдача Предметов на Склад в Бою и при PvP-Флаге

Защита от эксплойта спасения дропа в clan-handler.js и warehouse-handler.js

Medium Priority

В каноне Lineage 2 C1 любые складские операции (личный склад и CWH) строго запрещены при нахождении персонажа в состоянии боя (inCombat) или под действием PvP-флага (isFlagged), чтобы исключить мгновенное спасение экипировки от потери при гибели.
