1. Общие сведения и цели аудита

В MMO-сервере Project Steam: Origins сетевой стек оптимизирован для 3000–5000+ CCU на базе uWebSockets.js и бинарного Zero-Copy протокола. Однако предыдущий генератор стресс-теста создавал монотонную и неестественную нагрузку: боты просто бежали по прямой и спамили одну автоатаку, создавая нагрузку лишь на простейшие ветки кода.

Ключевая задача аудита: превратить нагрузочный тест в 100% реалистичную имитацию жизни сервера, где игроки торгуют в лавках на площади, заходят к NPC за баффами, садятся отдыхать на скамейки и в полях для регенерации, используют соулшоты и лечебные масла, общаются в трех каналах чата, кооперируются в группы и вызывают друг друга на дуэли.

2. Архитектура скриптов нагрузочного комплекса

Файл Назначение Технические особенности
scripts/stress-test-3000.js Ядро генерации живого онлайна Мультипроцессорный кластер воркеров, бинарный протокол NPB (0x01 UPD / 0x02 MOVE), 10 Hz единый цикл тика, Zero-GC.
scripts/run-stepped-benchmarks.js Ступенчатый стресс-раннер Плавное наращивание CCU (500 → 1000 → 2000 → 3000 → 5000), контроль зомби-процессов, сбор метрик памяти, тика и RTT.
scripts/trigger-gh-stress-test.js Запуск GitHub Actions через REST API Триггер workflow stress-test.yml в репозитории FatMAx123/Serv_test с передачей параметров нагрузки.
scripts/monitor-gh-workflow.js Мониторинг запущенного workflow Непрерывный опрос состояния раннеров GitHub Actions в реальном времени, вывод статуса и итогового отчета.
.github/workflows/stress-test.yml CI/CD Манифест тестирования Linux тюнинг TCP сокетов (ulimit -n 65535), автосохранение JSON/HTML отчетов и загрузка артефактов.

3. Выявленные недостатки исходного симулятора

№ Проблема Последствия для тестирования Решение в новой версии
1 Отсутствие личных торговых лавок Код store-handler.js не нагружался 25% городских ботов открывают Private Buy/Sell Stores (store_set), остальные читают витрины (store_list)
2 Игнорирование сервисных NPC Не тестировались баффер, торговцы, склад Горожане регулярно посещают Техника Биотина (npc_buff), Векса (shop_open) и Искру (wh_open)
3 Отсутствие тактической медицины и соулшотов Не тестировался use расходников в бою Авто-зарядка соулшотов, питьё synthetic_oil при HP < 65%, баллонов пара при MP < 35%
4 Отсутствие отдыха (Downtime Regen) Боты погибали с 5% HP без регенерации Боты садятся на землю (pose sitting: true) после боя для ускоренного регена HP/MP
5 Слепота к другим игрокам в AOI Боты не реагировали на окружающих Парсинг p сущностей в бинарном 0x01 UPD, приглашения в группы (party_invite), дуэли (duel_offer)
6 Пустой стартовый инвентарь ботов Боты не имели расходников и монет В server.js синтетическим ботам выданы соулшоты, масла, баллоны пара и стартовые медные детали

4. Четыре архетипа поведения (Player Archetypes)

Каждый создаваемый бот получает индивидуальный профиль и закрепляется за одним из 4 специализированных архетипов:

🏬 TownTrader
~25% от городских ботов
  • Занимает место на базаре или у кузницы
  • Садится на землю (pose sitting: true)
  • Открывает лавку продажи масел/зарядов или скупки руды
  • Периодически рекламирует лавку в +trade чат
  • Обрабатывает просмотры витрины другими игроками
🚶 TownCitizen
~75% от городских ботов
  • Прогуливается между ключевыми точками площади
  • Берёт баффы у Старшего Техника Биотина
  • Просматривает товары у Оружейника Векса
  • Заглядывает в лавки торговцев TownTrader
  • Отдыхает на скамьях, общается в all / shout
  • Периодически бросает вызовы на дуэль горожанам
⚔️ FieldHunter
~80% от полевых ботов
  • Охотится по всем 340 спотам острова Круна
  • Включает авто-зарядку соулшотов перед боем
  • Крутит полноценную классовую ротацию скиллов
  • Пьет масло synthetic_oil при HP < 65%
  • Пьет баллон pressure_canister при MP < 35%
  • Садится отдохнуть (Downtime Regen) при низком HP
  • Собирает выпавший трофейный лут
🛡️ FieldPartier
~20% от полевых ботов
  • Полный боевой функционал FieldHunter
  • Ищет ближайших свободных союзников на споте
  • Отправляет приглашения в пати (party_invite)
  • Принимает входящие инвайты (party_accept)
  • Совместно фокусирует и уничтожает сильных мобов
  • Участвует в групповом распределении опыта и лута

5. Городская экономика, торговые лавки и NPC

В городе симулируются полноценные торговые ряды Lineage 2 Classic. Торговцы используют канонический протокол пакета store_set: 

// Открытие личной торговой лавки
bot.send({
  t: 'store_set',
  mode: 'sell', // или 'buy'
  title: 'Заряды и Масла Дёшево!',
  items: {
    synthetic_oil: { count: 15, price: 45 },
    soulshot_no_grade: { count: 200, price: 12 },
    potion_alacrity: { count: 3, price: 350 }
  }
});

Горожане, проходящие мимо лавок, выполняют запрос store_list, создавая реалистичную нагрузку на подсистему торговли сервера. Визиты к NPC Технику Биотину генерируют запросы npc_buff_list и применение баффов npc_buff.

6. Боевой цикл, тактическая медицина и отдых

В полях боты ведут интеллектуальный бой в соответствии со своим классом:

8. Деплой и запуск нагрузочного теста в GitHub Actions

Все файлы синхронизированы в репозиторий FatMAx123/Serv_test (ветка main).

Способ 1: Запуск через консольный скрипт триггера

# Базовый запуск ступенчатого теста на боевой VPS (до 5000 CCU)
node scripts/trigger-gh-stress-test.js

# Запуск с кастомными параметрами (например, одиночный тест на 2000 CCU)
node scripts/trigger-gh-stress-test.js --mode=single --bots=2000 --town-bots=200 --duration=90

Способ 2: Мониторинг в реальном времени

node scripts/monitor-gh-workflow.js

Способ 3: Запуск через веб-интерфейс GitHub

  1. Перейдите по ссылке: https://github.com/FatMAx123/Serv_test/actions
  2. В списке слева выберите MMO Cluster Stepped Stress Test
  3. Нажмите кнопку Run workflow справа
  4. Выберите режим (stepped или single), укажите число ботов и нажмите зеленую кнопку запуска.
