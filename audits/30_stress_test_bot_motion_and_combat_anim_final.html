1. Почему боты отпружинивают назад (Rubberband Snap-back)?

В ходе стресс-тестирования при наблюдении за бегущими ботами было замечено регулярное «отпружинивание» (сжатие и отброс назад на 2–5 метров). Исследование исходного кода вскрыло два фундаментальных сбоя:

Дефект 1.1: Превышение серверного рейт-лимита RATE.move = 20 scripts/stress-test-3000.js:1279

В скрипте симуляции ботов шаг отправки пакета был установлен как movedSinceLastPacket >= 0.1 м. При базовой скорости бега Оператора/Инженера 7.5 м/с бот генерирует до 75 сетевых пакетов в секунду! 

// server/server.js:231
const RATE = { move:20, attack:8, action:6, chat:2, pvp:4, skill:10, npc:12 };
// server/server.js:5461
case 'move': {
  if (!checkRate(p, 'move')) return; // Отбрасывает 55 пакетов из 75 каждую секунду!

Сервер принимает первые 20 пакетов (первые 0.26 с), а затем замораживает координаты бота на 0.74 с. Бот локально продолжает бежать. На 5550 строке сервер детектирует расхождение координат и высылает принудительный пакет self_sync, который швыряет бота обратно к замороженным координатам на 5 метров назад.

Дефект 1.2: Отсутствие целевой точки destX/destZ в пакете NPB.encodeMove scripts/stress-test-3000.js:1285

Бот отправлял бинарный кадр без передачи конечной точки пути: NPB.encodeMove(this.x, this.z, this.isWalking, this.seq). Сервер в строке 5513 активирует вектор движения Dead Reckoning только при наличии цели: 

// server/server.js:5536
// Нет явной цели пути: НЕ проецируем фантомный вектор!
if (lastVec) {
  p._moveVec = null;
  broadcastMoveVecStop(p, c.x, c.z);
}

В итоге каждое движение бота воспринималось сервером как дискретный «микрошаг без вектора», сбрасывающий непрерывное векторное перемещение.

2. Почему боты дергаются при нагрузке на сервер (Jitter / Micro-stutter)?

В условиях высокой нагрузки (High Load) сервер переходит на динамическое квантование рассылки AOI (Tiered AOI):

  • Дистанция 16–45 м: рассылка позиций с частотой 5 Hz (каждые 200 мс).
  • Дистанция > 45 м: рассылка позиций с частотой 2.5 Hz (каждые 400 мс).

В клиентском коде client/js/net-ws.js:4416 координаты подтягивались через мгновенный экспоненциальный lerp (18 Гц): 

const lerpSpeed = dTarget > 1.2 ? 22 : (dTarget > 0.6 ? 18 : 14);
const k = Math.min(1.0, delta * lerpSpeed);
obj.position.x += (r.x - prevSx) * k;
obj.position.z += (r.z - prevSz) * k;

Модель преодолевает расстояние до серверной координаты за 80 мс, после чего намертво встает на 120–320 мс, ожидая следующий пакет от сервера. Приход пакета снова толкает модель. Результат — постоянная дерганая «икота» перемещения.

Архитектурное Решение: Snapshot Interpolation & Velocity Smoothing Решение

Сохранение расчетного вектора скорости _velX, _velZ и межпакетная плавная экстраполяция на время до 140 мс при задержках пакетов. Пока следующий пакет летит по сети, модель продолжает плавно скользить вперед по направлению движения, полностью ликвидируя микрофризы между тиками.

3. Почему игроку не видно анимаций автоатаки ботов?

Когда бот атакует моба или игрока, сервер отсылает пакеты урона: 

// server/server.js:5728 (PvE)
broadcastAOI(p, {
  t: 'dmg', mid: m.mid, dmg: hit.damage, crit: hit.crit, by: p.pid,
  facing: attackFacing, atkInterval: pack.atkIntervalMs
});

Клиентский обработчик в client/js/net-ws.js:1453 (для PvE dmg) и 1518 (для PvP dmg_player):

  • Показывает урон в воздухе showDamageNumber.
  • Проигрывает звуковой эффект GameAudio.play('hit').
  • Анимирует моба SkillVFX.playCombatHit.
  • НО ВООБЩЕ НЕ ВЫЗЫВАЕТ АНИМАЦИЮ У АТАКУЮЩЕГО!

В строках 1453–1517 нет ни единого упоминания модели атакующего attacker._charModel.playAttack()! В итоге боты наносят урон мобам, стоя как неподвижные столбы.

Исправление в client/js/net-ws.js Решение 
const attackerKey = (typeof m.by === 'number' || (typeof m.by === 'string' && m.by[0] !== 'p' && m.by[0] !== 'm')) ? ('p' + m.by) : String(m.by);
const attacker = this.remote.get(attackerKey);
if (attacker && attacker._charModel && typeof attacker._charModel.playAttack === 'function') {
  if (m.facing != null) attacker._charModel.setFacing(m.facing);
  const atkDur = (m.atkInterval ? m.atkInterval / 1000 : 0.65);
  attacker._charModel.playAttack(atkDur);
}

4. Почему игроку не видно анимаций скилов ботов?

Здесь выявлены сразу 2 дефекта — на стороне симулятора ботов и на стороне визуального клиента:

Дефект 4.1: Ошибочные ID скилов в ротации ботов scripts/stress-test-3000.js:1230, 1239

В скрипте стресс-теста бот отсылает скилл op_steam_slash для Оператора и eng_steam_vent для Инженера. В канонической базе скиллов shared/skill-db.js скилла op_steam_slash не существует, а eng_steam_vent принадлежит Оператору! Сервер отклоняет такие запросы с failSkill('not_learned'), поэтому пакеты skill_fx даже не транслировались в сеть.

Дефект 4.2: Отсутствие вызова анимации модели в case 'skill_fx' client/js/net-ws.js:2151

Когда сервер присылает пакет skill_fx, клиент создавал партиклы SkillVFX.playSkill(...), но скелетная модель персонажа кастера caster._charModel.playCast(...) или playSkill(...) не активировалась.

5. Почему игроку не видно анимацию смерти персонажей?

При гибели игрока или бота сервер рассылает по AOI пакет { t: 'player_dead', pid: p.pid }. Посмотрим на клиентский обработчик в client/js/net-ws.js:1693: 

case 'player_dead': {
  const pdeadPos = m.pid != null ? this.posOf('p' + m.pid) : null;
  if (window.GameAudio && typeof window.GameAudio.play === 'function') {
    window.GameAudio.play('death', pdeadPos);
  }
  g.addChatMessage('Игрок повержен в PvP.', 'damage');
  break;
}

Обработчик только играет звук и добавляет строку в чат! Запись погибшего this.remote.get('p' + m.pid) не запрашивается, флаги смерти не выставляются, анимация r._charModel.playDeath() не вызывается. Погибший персонаж продолжает стоять вертикально в анимации покоя (idle), пока через 2 секунды не респавнится.

Сводка реализованных модулей

1. Движение Ботов (Anti-Rubberband & Zero-Jitter)

  • В scripts/stress-test-3000.js частота сетевых пакетов move ограничена 10 Гц (шаг не чаще 0.65м или 0.25м раз в 2 тика).
  • Ликвидировано превышение RATE.move = 20 (устранен сброс 55 пакетов/с сервером и заморозка).
  • В NPB.encodeMove и JSON передаются destX, destZ (вектор цели), предотвращая остановку на сервере.
  • В client/js/net-ws.js порог аварийного сброса вектора поднят до 6.0м; внедрено мягкое подтягивание (25% в кадр) при рассинхроне 0.8–6.0м.
  • Активирована межпакетная экстраполяция _extrapolateUntil для бесшовного движения при 5 Hz / 2.5 Hz AOI.

2. Визуализация Боевых Анимаций

  • Автоатака: В case 'dmg' и case 'dmg_player' внедрен поиск атакующего и вызов attacker._charModel.playAttack() с доворотом к цели.
  • Скиллы (ID): В scripts/stress-test-3000.js исправлены ID на канонические (Оператор: op_power_strike, op_iron_punch; Инженер: eng_pressure_bolt, eng_curse_corrode).
  • Скиллы (Анимация): В case 'cast_start' и case 'skill_fx' кастер разворачивается к цели и выполняет caster._charModel.playCast(...).
  • Смерть: В case 'player_dead' модель погибшего бота/игрока выполняет remDeadP._charModel.playDeath() и фиксирует isDead = true.
