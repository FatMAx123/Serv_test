## 1. Резюме и Цели Аудита

Настоящий аудит посвящён детальному анализу, оптимизации и модернизации подсистемы нагрузочного стресс-тестирования MMO-сервера (`Project Steam: Origins`).  
Основная задача: трансформировать синтетический генератор нагрузки из примитивного эмулятора сокетов в **полноценную систему имитации реальной жизни игроков на сервере** (Multi-Archetype Player Life Simulation), покрывающую все ключевые игровые и сетевые подсистемы MMO:
1. **Городская экономика и социальная жизнь**: Личные торговые лавки игроков (Private Buy/Sell Stores по канону Lineage 2 Classic), просмотр витрин торговцев, взаимодействие с сервисными NPC (баффер Техник Биотин, оружейник Векс, бакалейщик Милли, склад Искра), отдых на скамьях, многоканальный живой чат (`all`, `shout`, `trade`), дружеские вызовы на дуэли (`/duel`).
2. **Полевая охота и боевой цикл**: Охота на мобов по всем 340 спотам острова, классовые ротации скиллов (Оператор и Инженер), автоматическая зарядка соулшотов и спиритшотов (`use`), применение лечебных масел (`synthetic_oil`) и баллонов пара (`pressure_canister`) при просадках HP/MP, сбор выпавшего лута (`loot_pickup`), тактическое позиционирование и маневрирование.
3. **Тактический отдых (Downtime Rest & Regeneration)**: Переход в позу отдыха сидя (`pose sitting: true`) в безопасных зонах после тяжелого боя для ускоренной регенерации HP/MP с последующим подъёмом и продолжением прокачки.
4. **Кооперация и группы**: Динамическое объединение полевых ботов в группы (Parties) через `party_invite` и `party_accept` с совместным фокусом целей.
5. **Деплой и запуск через GitHub Actions**: Полная интеграция и актуализация токенов, скриптов запуска (`trigger-gh-stress-test.js`), мониторинга (`monitor-gh-workflow.js`) и workflow (`stress-test.yml`) в репозитории `FatMAx123/Serv_test`.

## 3. Выявленные Дефекты и Недостатки Исходных Скриптов

В ходе детального аудита исходной кодовой базы нагрузочного тестирования были выявлены следующие архитектурные пробелы:

1. **Отсутствие дифференциации архетипов поведения (Поверхностная жизнь)**:
   - Боты делились только на «городских» и «полевых» по жесткому индексу.
   - Городские боты просто ходили по 13 точкам площади и спамили одну и ту же фразу в общий чат.
   - Полностью отсутствовала экономическая активность: ни один бот не открывал торговые лавки, не покупал и не продавал предметы.
2. **Отсутствие взаимодействия с сервисными NPC**:
   - В городе присутствуют канонические NPC: Старший Техник Биотин (`biotin`, NPC баффер), Оружейник Векс (`trader_vex`), Бронник Дора (`trader_dora`), Кладовщица Искра (`grocer_spark`).
   - Исходные боты полностью игнорировали NPC и никогда не запрашивали баффы, диалоги или списки товаров.
3. **Примитивный боевой цикл в полях**:
   - Боты спамили автоатакой или одним единственным скиллом без ротации.
   - Боты не использовали расходники: ни соулшоты/спиритшоты для ускорения фарма, ни лечебные масла (`synthetic_oil`) при опасном падении здоровья, ни баллоны пара (`pressure_canister`) при исчерпании маны.
   - Отсутствовал канонический цикл отдыха (Downtime Rest): реальный игрок в Lineage 2 при просадке HP садится на землю (`pose sitting: true`), чтобы восстановить HP/MP втрое быстрее. Исходные боты бежали на моба с 5% HP и погибали.
4. **Игнорирование других игроков (Слепота AOI)**:
   - При парсинге бинарных пакетов `0x01 UPD` отслеживались только сущности мобов (`m`). Сущности игроков (`p`) отбрасывались.
   - Боты не видели друг друга, не могли кооперироваться в группы (Parties), не предлагали дуэлей и не заглядывали в чужие лавки.
5. **Недостаточность стартового снаряжения синтетических ботов на сервере**:
   - В `server/server.js` в функции `doLoginInner` метод `isSyntheticBot` выдавал ботам базовое оружие и 3 скилла, но оставлял инвентарь `inv` пустым (0 монет, 0 расходников, 0 соулшотов). Из-за этого боты не могли открывать магазины и пить зелья.
6. **Устаревший токен GitHub Actions и захардкоженные параметры**:
   - В файлах `trigger-gh-stress-test.js` и `monitor-gh-workflow.js` содержался устаревший токен с истекшим сроком действия.

## 4. Новая Архитектура: Имитация Жизни на Сервере (Multi-Archetype Player Life Simulation)

В обновлённом движке `scripts/stress-test-3000.js` реализованы 4 взаимосвязанных архетипа поведения с глубокими конечными автоматами (FSM):

```
                                  [ВХОД ИГРОКА / Welcome]
                                             │
                      ┌──────────────────────┴──────────────────────┐
                      ▼                                             ▼
          [ГОРОДСКИЕ ЖИТЕЛИ (Town)]                     [ПОЛЕВЫЕ ОХОТНИКИ (Field)]
                      │                                             │
         ┌────────────┴────────────┐                   ┌────────────┴────────────┐
         ▼                         ▼                   ▼                         ▼
 ┌───────────────┐         ┌───────────────┐   ┌───────────────┐         ┌───────────────┐
 │  TownTrader   │         │  TownCitizen  │   │  FieldHunter  │         │ FieldPartier  │
 │ (Торговцы на  │         │  (Горожане,   │   │(Соло-охотники,│         │ (Охотники в   │
 │   базаре)     │         │ прогулки/NPC) │   │скиллы, банки) │         │    группе)    │
 └───────┬───────┘         └───────┬───────┘   └───────┬───────┘         └───────┬───────┘
         │                         │                   │                         │
   • Торговые лавки          • Визиты к Биотину  • Ротация скиллов         • Приглашение в
     (store_set)               за баффами          (Operator/Eng)            группу (party)
   • Продажа масел,          • Осмотр витрин     • Соулшоты (use)          • Совместный фокус
     зарядов, руды           • Отдых на скамьях  • Лечебные масла HP       • Дележ лута
   • Реклама в Trade-чат     • Локальный чат     • Отдых сидя (Regen)      • Взаимовыручка
```

### 4.1. Архетип `ARCHETYPE_TOWN_TRADER` (Торговцы площади)
* **Численность**: ~25% от городских ботов.
* **Поведение**:
  - Занимает одну из 10 канонических торговых точек (Восточный базар, Мастерские кузнеца, сквер у фонтана).
  - Садится на коврик/землю (`pose sitting: true`).
  - Разворачивает личную торговую лавку (`store_set`) по канону Lineage 2 Classic в одном из режимов:
    - **Продажа расходников**: Синтетическое масло (`synthetic_oil`), баллоны пара (`pressure_canister`), заряды No-Grade (`soulshot_no_grade`), зелья скорости (`potion_alacrity`).
    - **Скупка сырья**: Скупка медной руды (`copper_ore`) и обломков шестерней (`gear_scrap`).
  - Раз в ~60–80 секунд транслирует торговое объявление в глобальный канал `+trade` («WTS Соулшоты x500 по 12 деталей», «WTB Медную руду и шестерни дорого»).

### 4.2. Архетип `ARCHETYPE_TOWN_CITIZEN` (Активные горожане)
* **Численность**: ~75% от городских ботов.
* **Поведение**:
  - Непрерывное плавное перемещение между ключевыми городскими достопримечательностями с использованием Dead Reckoning.
  - **Взаимодействие с NPC**:
    - Подходит к Старшему Технику Биотину (`x: 35.8, z: -98.2`) и запрашивает список баффов (`npc_buff_list`), после чего получает бафф силы/защиты (`npc_buff`).
    - Подходит к Оружейнику Вексу и торговцам, открывая каталог магазина (`shop_open`).
    - Проверяет склад у Кладовщицы Искры (`wh_open`).
  - **Экономическое взаимодействие**: Проходя мимо лавок `TownTrader`, останавливается и просматривает товары через `store_list`.
  - **Социальные действия**: Присаживается на городские скамейки для отдыха, встает перед продолжением пути, отправляет реплики в общий локальный чат (`chat ch: 'all'`) и выкрики (`chat ch: 'shout'`).
  - **PvP-активность**: Периодически бросает дружеские вызовы на дуэль (`duel_offer`) стоящим рядом горожанам.

### 4.3. Архетип `ARCHETYPE_FIELD_HUNTER` (Полевые соло-охотники)
* **Численность**: ~80% от полевых ботов.
* **Поведение**:
  - Распределяется по 340 охотничьим спотам Острова Круна.
  - **Боевая подготовка**: Перед началом атаки включает авто-зарядку соулшотов или спиритшотов (`use soulshot_no_grade`).
  - **Классовая ротация скиллов**:
    - *Оператор*: чередует сокрушительный удар (`op_power_strike`), оглушающий тычок (`op_iron_punch`) и паровой выброс (`op_steam_vent`).
    - *Инженер*: использует напорный снаряд (`eng_pressure_bolt`), коррозийное проклятие (`eng_curse_corrode`) и откачку давления (`eng_pressure_drain`).
  - **Тактическая медицина**:
    - При падении здоровья ниже 65% выпивает восстанавливающее синтетическое масло (`use synthetic_oil`).
    - При падении маны ниже 35% использует баллон сжатого пара (`use pressure_canister`).
  - **Тактический отдых (Downtime Rest)**: После победы над мобом, если HP < 50% или MP < 40%, и рядом нет агро-мобов, садится на землю (`pose sitting: true`), удваивая скорость регенерации до восстановления 90% ресурсов, после чего поднимается и продолжает путь.
  - **Сбор лута**: Обнаружив выпавший трофей (`loot_spawn`), прерывает блуждание, подбегает к точке и забирает предмет (`loot_pickup`).

### 4.4. Архетип `ARCHETYPE_FIELD_PARTIER` (Групповые охотники)
* **Численность**: ~20% от полевых ботов.
* **Поведение**:
  - В дополнение к функционалу `FieldHunter` сканирует близлежащих игроков (`knownPlayers`).
  - Если не состоит в группе, отправляет приглашение в группу (`party_invite`) ближайшему свободному боту.
  - Получив приглашение, с высокой вероятностью соглашается (`party_accept`), формируя боевые двойки и тройки, совместно зачищающие споты.

## 5. Оптимизация Производительности Симулятора (Zero-GC и 10 Hz Loop)

1. **Единый диспетчер симуляции (Zero-Timer Architecture)**:
   - В симуляторе **категорически запрещены** индивидуальные таймеры `setInterval` / `setTimeout` на каждого бота. При 5 000 ботов это создавало бы 50 000+ таймеров в пуле Node.js, вызывая деградацию таймерного дерева V8.
   - Вся симуляция координируется **одним единственным системным таймером** с частотой 10 Hz (`setInterval` с `dt = 0.1c`).
2. **Шахматное распределение пакетов (Staggered Networking)**:
   - Все вторичные действия (проверка баффов, пинг, просмотр лавок, сообщения чата, использование зелий) разнесены по модулю тика: `tick % interval === (bot.index % interval)`.
   - Это гарантирует абсолютно гладкий сетевой профиль без пакетных штормов.
3. **Строгое соблюдение серверных лимитов (Rate-Limit Compliance)**:
   - Частота действий ботов строго согласована с серверными лимитерами `checkRate(p, 'action')` и `checkRate(p, 'chat')`, предотвращая дисконнекты за спам.

## 7. Деплой и Инструкция по Запуску в GitHub Actions

### 7.1. Синхронизация с GitHub
Все изменения синхронизированы в выделенное зеркало `scratch/serv_test` и отправлены в GitHub:
* **Репозиторий**: `https://github.com/FatMAx123/Serv_test`
* **Ветка**: `main`
* **Workflow**: `.github/workflows/stress-test.yml`

### 7.2. Запуск через скрипт триггера (CLI)
Для запуска стресс-теста из локальной консоли:
```bash
node scripts/trigger-gh-stress-test.js
```
Скрипт поддерживает переменные окружения и аргументы командной строки:
```bash
node scripts/trigger-gh-stress-test.js --mode=stepped --start=1000 --max=5000 --step=1000 --duration=60 --town-bots=250 --workers=4
```

### 7.3. Мониторинг выполнения в реальном времени
Сразу после отправки триггера запустите скрипт мониторинга:
```bash
node scripts/monitor-gh-workflow.js
```
Скрипт подключается к GitHub REST API, отслеживает инициализацию раннеров, выводит текущий статус каждые несколько секунд и фиксирует финальный результат.

### 7.4. Ручной запуск через веб-интерфейс GitHub Actions
1. Откройте в браузере: `https://github.com/FatMAx123/Serv_test/actions`
2. В левой колонке выберите воркфлоу: **MMO Cluster Stepped Stress Test**
3. Нажмите кнопку **Run workflow** справа
4. Задайте желаемые параметры:
   - **Режим**: `stepped` (ступенчатый) или `single` (одиночный).
   - **Хост**: `93.77.168.135` (боевой VPS).
   - **Порт**: `80`.
   - **Городские боты**: `250` (активная площадь, лавки, чат, NPC).
   - **Максимальный онлайн**: `5000` CCU.
5. Нажмите зелёную кнопку **Run workflow**.
