1. Архитектурная Цель и Проблематика Чистого JS

При росте нагрузки до 1500–2000 CCU на 2 vCPU процессорное время тика (100 мс) распределяется между сетевым I/O и игровой симуляцией. В чистом JavaScript пространственная сетка SpatialGrid тратит до 6–10 мс на обход ячеек, хэш-ключей и сканирование соседей.

Ограничения V8, устраненные нативным C++ аддоном:
  • Отсутствие аппаратного SIMD: В C++ интринсики AVX2 обрабатывают 8 сущностей за 1 процессорный такт (_mm256_sub_ps, _mm256_mul_ps, _mm256_add_ps, _mm256_cmp_ps).
  • Кэш-промахи и ссылки: Структуры данных JS Map/Array разбросаны в куче. Нативная сетка C++ представляет собой сплошной плоский массив байт.
  • Zero FFI Overhead: Исключены единичные вызовы на сущность; взаимодействие строится на едином разделяемом буфере Float32Array (Bulk Ingestion).

2. Векторизация Расчета Дистанций через AVX2 SIMD

При выборке сущностей в радиусе $R$ нативный движок загружает координаты кандидатов в 256-битные регистры YMM:

// Загрузка координат 8 кандидатов за 1 машинную инструкцию: __m256 v_cand_x = _mm256_load_ps(cand_x); __m256 v_cand_z = _mm256_load_ps(cand_z); __m256 v_dx = _mm256_sub_ps(v_cand_x, v_target_x); __m256 v_dz = _mm256_sub_ps(v_cand_z, v_target_z); __m256 v_dist2 = _mm256_add_ps(_mm256_mul_ps(v_dx, v_dx), _mm256_mul_ps(v_dz, v_dz)); // Векторное сравнение с квадратом радиуса (8 результатов сразу): __m256 v_mask = _mm256_cmp_ps(v_dist2, v_radius2, _CMP_LE_OQ); int mask = _mm256_movemask_ps(v_mask);

Битовая маска mask моментально определяет, какие из 8 кандидатов попадают в радиус видимости, исключая ветвления и промахи предсказателя переходов процессора (Branch Misprediction).

3. Shared Memory Interface (Bulk Ingestion)

Вместо сотен отдельных вызовов grid.insertPlayer() / grid.insertMob() C++ модуль принимает прямой указатель на память Float32Array из таблицы трансформов EntityTransformTable:

// JS-вызов: 1 вызов на весь такт! nativeSpatialGrid.bulkInsert(entityTransforms.buffer, entityTransforms.maxSlot); // В C++: прямое чтение сырого указателя float* без единого байта копирования float* data = (float*)napi_buffer_data; for (int i = 0; i < entityCount; i++) { int offset = i * 8; int type = (int)data[offset + 6]; if (type <= 0) continue; float x = data[offset + 0]; float z = data[offset + 2]; float hp = data[offset + 3]; int id = (int)data[offset + 7]; grid.insert(id, type, x, z, hp, hp <= 0); }

6. Dual-Engine Transparent Fallback

Система спроектирована по принципу «Graceful Degradation»:

// server/spatial-grid.js let nativeModule = null; try { nativeModule = require('../build/Release/project_steam_native.node'); } catch (e) { nativeModule = null; // Прозрачный фолбэк на чистый JS } module.exports = { SpatialGrid, NativeSpatialGrid: nativeModule ? nativeModule.NativeSpatialGrid : null, fastDistance2: nativeModule ? nativeModule.fastDistance2 : null };

Это гарантирует бесперебойную работу тестов в CI/CD и разработку без необходимости обязательной компиляции C++.
