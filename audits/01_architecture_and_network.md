# 1. Архитектура Движка и Сетевой Протокол
**Project Steam — Техническая Документация Подсистем**

---

## 1.1. Клиент-Серверная Модель (Server Authority)

Вся игровая логика Project Steam построена на принципе **абсолютного авторитета сервера (100% Server Authority)**:
- Серверная часть (`server/server.js`) на базе Node.js WebSocket является единственным источником правды о состоянии игрового мира.
- Клиент на базе Three.js (`client/js/`) функционирует как проекционный терминал: он считывает пользовательский ввод и отправляет на сервер исключительно **намерения** (`intent`):
  - `intentMove`: целевые координаты движения и вектор рыскания (Yaw).
  - `intentAttack`: запрос на совершение автоатаки по выбранной цели.
  - `intentCast`: запрос на активацию программы контура (заклинания) с проверкой дистанции, кулдауна и пара (MP).
  - `intentUseItem`: запрос на использование расходуемого предмета (заряды, ремкомплекты, эликсиры).
  - `intentTrade`: запрос на открытие защищенной торговой сессии между игроками.
  - `intentClassTransfer`: подтверждение перехода на первую специализацию.
- Сервер выполняет строгую валидацию каждого пакета:
  - Проверка дистанции (Range Check) с компенсацией сетевой задержки.
  - Проверка коллизий с 3D-препятствиями и высоты рельефа.
  - Контроль кулдаунов способностей и скорости атаки.
  - Валидация наличия зарядов и ресурсов в инвентаре.
  - Исключение возможности вмешательства со стороны клиента (SpeedHack, RangeHack, NoClip, FlyHack, Injection).

## 1.2. Сетевой Транспорт и Бинарный Протокол

Для обеспечения стабильного фреймрейта (60 FPS) и минимизации сетевого трафика на мобильных устройствах внедрен гибридный протокол обмена данными:

### 1.2.1. Бинарная Упаковка Движения (`client/js/net-pack-binary.js`)
Высокочастотные пакеты движения и синхронизации позиций упаковываются в бинарные структуры (`ArrayBuffer` / `DataView`):

| Байт смещения | Тип данных | Назначение | Описание |
|:---:|:---:|:---|:---|
| `0..1` | `uint16` | `packetType` | Идентификатор бинарного пакета движения (`0x0101`) |
| `2..5` | `int32` | `entityId` | Уникальный ID сущности (игрок или моб) |
| `6..7` | `int16` | `posX` | Координата X в дециметрах (дискретизация 0.05 м) |
| `8..9` | `int16` | `posZ` | Координата Z в дециметрах (дискретизация 0.05 м) |
| `10..11` | `int16` | `yaw` | Угол поворота персонажа (квантован в диапазон `-32768..32767`) |
| `12` | `uint8` | `flags` | Битовая маска состояний: `0x01` — бег/шаг, `0x02` — боевая стойка, `0x04` — сидит |

**Эффективность**: Размер кадра движения сокращен со **120 байт (JSON)** до **13 байт (Binary)**. Снижение нагрузки на сетевой стек составляет более **89%**.

## 1.3. Многоуровневая Область Интереса (Tiered AOI)

Для исключения лагов при скоплении сотен игроков в Деревне Круна или на рейдовых боссах сервер использует систему трехполосного пространственного квантования (Tiered Area of Interest):

```
                        [ Игрок (Центр) ]
                               │
       ┌───────────────────────┼───────────────────────┐
       ▼                       ▼                       ▼
  [ Tier 1: Ближний бой ]  [ Tier 2: Средняя зона ]  [ Tier 3: Горизонт ]
    Дистанция: <= 16м       Дистанция: 16 – 45м      Дистанция: > 45м
    Частота: 10 Hz (100мс)  Частота: 5 Hz (200мс)    Частота: 2.5 Hz (400мс)
```

- **Принудительный импульс (Sharp Move)**: Если любая сущность перемещается более чем на **2.5 метра за один серверный тик**, ее координаты рассылаются вне очереди с приоритетом Tier 1, предотвращая визуальные рывки при рывках или телепортации.

## 1.4. Пространственный Хэш (Spatial Hash Grid)

Высота поверхности (`standY`) и физические коллизии с окружающими объектами рассчитываются без использования тяжелых геометрических лучей Three.js (`Raycaster`):
- **Сетка $16 \times 16$ метров**: Вся карта Острова Круна разделена на ячейки Spatial Hash Grid.
- **131 Коллизионный Проп**: Здания, шестерни, трубы, заборы, мосты и скалы индексируются по ячейкам при инициализации мира.
- **Производительность**: Определение высоты под ногами персонажа и проверка на столкновение выполняется за **$< 1$ микросекунды** (в 1500 раз быстрее перебора полигонов), гарантируя гладкий фреймрейт без микрофризов.

---

## 1.5. Отложенная Запись Профилей (Write-Behind Cache)

Для защиты сервера от блокировок Event Loop при частых транзакциях (получение лута, начисление опыта, торговля):
- Измененный профиль игрока помечается как «грязный» (`dirtyProfiles.add(playerId)`).
- Сброс на диск выполняется асинхронной пакетной записью через заданные интервалы времени.
- При выходе игрока из игры или плановом перезапуске сервера вызывается метод принудительной синхронизации `DB.flush()`.
