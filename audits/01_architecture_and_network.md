# 1. Архитектура Движка и Сетевой Протокол
**Project Steam: Origins — Техническая Документация Подсистем (Production Stack 5 100+ CCU)**

---

## 1.1. Клиент-Серверная Модель и Zero-Rollback Инварианты

Вся игровая логика Project Steam построена на принципе **абсолютного авторитета сервера (100% Server Authority)** в строгом соответствии с политикой `AGENTS.md` (Zero Rollback Policy):
- Серверное ядро (`server/server.js`) на базе нативного C++ сетевого транспорта и Node-API модулей является единственным источником правды о состоянии игрового мира.
- Клиент на базе Three.js (`client/js/`) функционирует как проекционный терминал: он считывает пользовательский ввод и отправляет на сервер исключительно **намерения** (`intent`):
  - `intentMove`: целевые координаты движения и вектор рыскания (Yaw).
  - `intentAttack`: запрос на совершение автоатаки по выбранной цели.
  - `intentCast`: запрос на активацию программы контура (заклинания) с проверкой дистанции, кулдауна и пара (MP).
  - `intentUseItem`: запрос на использование расходуемого предмета (заряды, ремкомплекты, эликсиры).
  - `intentCraft`: запрос на сборку предмета по изученному чертежу.
  - `intentPrivateStore`: запрос на открытие личной торговой лавки или мануфактуры (включая оффлайн-режим).
  - `intentTrade`: запрос на открытие защищенной сессии обмена между игроками.
- Сервер выполняет строгую авторитарную валидацию каждого пакета:
  - Защита от спидхака: лимит скорости `clampSpeed` с прерыванием пакетов при превышении.
  - Проверка дистанции (Range Check) с компенсацией задержки RTT.
  - Проверка коллизий с 3D-препятствиями и удержание на геодате.
  - Валидация наличия зарядов и ресурсов в серверном инвентаре.
  - Исключение вмешательства со стороны клиента (SpeedHack, RangeHack, NoClip, FlyHack, Injection).

## 1.2. Сетевой Транспорт: C++ Zero-GC uWebSockets.js v20.70.0

В продакшене сервер функционирует исключительно на нативном C++ сетевом транспорте **uWebSockets.js** (`server/net-transport.js`, параметры `NET_ENGINE: 'uws'`, `STRICT_UWS: '1'`):
- **Прямая работа с epoll ядра Linux:** Устранены накладные расходы Node.js HTTP/WS стека.
- **Zero-GC Pub/Sub:** Рассылка пакетов в области видимости (AOI) выполняется через нативные C++ топики без аллокаций в куче V8, что полностью устраняет паузы сборщика мусора (GC Pauses).
- **Масштабируемость:** Подтвержденная стабильная поддержка **5 100+ одновременных активных соединений (CCU)** на 2 vCPU.
- **Fail-Fast Policy:** Сервер не откатывается на устаревший чистый JS `ws`. При отсутствии бинарника uWS запуск аварийно прерывается до устранения проблемы компиляции.

## 1.3. Нативный C++ SIMD Боевой Движок (`project_steam_native.node`)

Критические высоконагруженные вычисления вынесены в скомпилированный C++ модуль (`native/src/main.cpp`, `combat_engine.h`, `spatial_grid.h`) с оптимизациями компилятора `-O3 -mavx2`:
1. **SIMD AVX2 Боевая Математика:**
   - Пакетная обработка атак `resolveBatchAttacks`: расчет точности, уклонения, P.Atk, P.Def, критов и соулшотов векторными регистрами 256 бит.
   - Скорость вычислений: **0.20 мс на 100 000 атак** (в 35–40 раз быстрее эквивалентного JavaScript-кода).
2. **Нативный Spatial Grid:**
   - 2D-сетка хеширования с квантованием ячеек.
   - Поиск кандидатов на урон, агро и AOI выполняется за **$< 1$ микросекунды**.

## 1.4. Разгрузка I/O через Worker Threads (vCPU 2 Offload)

Для гарантированного поддержания частоты тика сервера 10 Hz (100 мс) без задержек Event Loop:
- Подсистемы сериализации JSON, взаимодействия с БД (PostgreSQL / SQLite) и дискового I/O вынесены в фоновый рабочий поток (`server/workers/persistence-worker.js`).
- Клиент персистентности (`server/workers/persistence-client.js`) передает данные через потокобезопасные сообщения `MessagePort`.
- Главный цикл симуляции мира освобожден от синхронного и тяжелого дискового ввода-вывода (0 мс влияния I/O на игровой тик).

## 1.5. Data-Oriented Design (DOD) и Дельта-Сжатие Движения

Для масштабирования до 5 100 CCU на ограниченной памяти:
- **`EntityTransformTable` (SoA):** Координаты всех сущностей хранятся в непрерывном массиве `Float32Array` (32 байта на сущность, точно под размер строки кэша L2).
- **Бинарная дельта движения (13 байт):**
  
| Байт | Тип | Назначение | Описание |
|:---:|:---:|:---|:---|
| `0..1` | `uint16` | `packetType` | `0x0101` (бинарный маркер движения) |
| `2..5` | `int32` | `entityId` | Уникальный сетевой ID сущности |
| `6..7` | `int16` | `posX` | Координата X в дециметрах (дискретизация 0.05 м) |
| `8..9` | `int16` | `posZ` | Координата Z в дециметрах (дискретизация 0.05 м) |
| `10..11` | `int16` | `yaw` | Угол рыскания (`-32768..32767`) |
| `12` | `uint8` | `flags` | Битовая маска: бег/шаг, боевая стойка, сидит |

- **Dead Reckoning & Adaptive Lerp:** Интерполяция движения сглаживает сетевой джиттер (Zero-Jitter), а функция Ground Snap устраняет визуальное зависание в воздухе при появлении сущностей.

## 1.6. Многоуровневое Квантование (Tick-LOD и Tiered AOI)

1. **Алгоритмический Tick-LOD (Снижение вычислений на 65%):**
   - **Tier 0 (10 Hz / 100 мс):** Боевой режим, каст способностей, рейдовые боссы, ивенты.
   - **Tier 1 (2 Hz / 500 мс):** Небоевое блуждание, сканирование агро мирных мобов.
   - **Tier 2 (0.33 Hz / 3 000 мс):** Полный переход в спящий режим для мобов на дистанции $> 155$ м от реальных игроков.
2. **Tiered Area of Interest (AOI):**
   - **Close/Combat ($r \le 16$ м):** Частота обновления 10 Hz (100 мс).
   - **Mid ($16 < r \le 45$ м):** Частота обновления 5 Hz (200 мс).
   - **Far ($r > 45$ м):** Частота обновления 2.5 Hz (400 мс).
   - **Лимиты видимости:** Для игроков — 128 (soft) / 160 (hard), для синтетических ботов — 24 / 32.
   - **Импульс резкого сдвига:** При перемещении $> 2.5$ м за тик пакет отсылается вне очереди с приоритетом Tier 0.

## 1.7. Сетевой Харденинг и Защита от DDoS (Аудиты 35–36)

Сетевой стек защищен на уровнях L4 и L7:
- **Пре-парсинг рейт-лимиты:** Отсечение флуд-пакетов (порог 40 msg/s) **до вызова `JSON.parse`**, предотвращая деградацию Event Loop при спаме сокетов.
- **Ограничение соединений:** Лимитирование одновременных сокетов с одного IP (HTTP 429).
- **Жесткие таймауты:** 15 секунд на авторизацию после подключения, 45 секунд на idle-таймаут неактивных сокетов.
- **Семафор PBKDF2:** Параллельное криптографическое хеширование паролей ограничено 3 потоками для защиты от DoS-атак через спам авторизацией.
- **Сброс медленного TCP Backpressure:** При переполнении буфера отправки сокета более 1 МБ соединение принудительно разрывается.
