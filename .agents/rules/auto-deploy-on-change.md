# Правило: Автоматический деплой силами AI-агента (Zero Manual Deploy)

## Главный императив
Пользователь **НЕ ДОЛЖЕН** руками вызывать команды деплоя, сборки или коммитов.
AI-агент **ОБЯЗАН АВТОНОМНО** в конце каждого цикла работы, где производились изменения исходного кода, запускать деплой через инструмент запуска команд (`run_command`) перед отправкой финального ответа пользователю.

---

## 1. Протокол при изменении КЛИЕНТА (`client/`, `shared/`)
Если агент изменил клиентские файлы:
1. Выполнить сборку: `node scripts/build-client.js`
2. Выполнить деплой на Render: `node scripts/deploy-render.js`
3. Выполнить синхронизацию на боевой VPS: `node scripts/sync-client-vps.js`
4. Зафиксировать и отправить в GitHub: `git add -A && git commit -m "..." && git push origin main`

---

## 2. Протокол при изменении СЕРВЕРА (`server/`, `data/`, `native/`, `shared/`, `ecosystem.config.js`, `binding.gyp`)
Если агент изменил серверные файлы:
1. Проверить инварианты: `node scripts/guard-anti-rollback.js`
2. Выполнить полный деплой на VPS (сборка C++, перенос, reload PM2): `node scripts/deploy-vps.js`
3. Зафиксировать и отправить в GitHub: `git add -A && git commit -m "..." && git push origin main`

---

## 3. Универсальный запуск (Рекомендуется)
Агент может запустить единый умный оркестратор, который сам определит тип изменений и выполнит всю цепочку автоматически:
```bash
node scripts/auto-deploy-all.js "Точное описание изменений"
```

---

## 4. Строгие запреты для агента
* **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** писать пользователю «теперь выполните в терминале команду деплоя...». Вся процедура выполняется агентом под ключ.
* **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** оставлять завершенные правки локально незакоммиченными или незадеплоенными на целевые боевые сервера.
