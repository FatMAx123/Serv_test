# Audit Lifecycle Manager (Пайплайн Игровых Аудитов и Постреализации)

Регламент проведения, структурирования, архивации и постреализационной фиксации всех аудитов игровых систем в проекте (MMORPG Lineage 2 C1 Steampunk Conversion).

---

## 1. Архитектура Директории `audits/`

Все результаты анализов, математических расчетов, проверок баланса, лора и отчетов о реализации сохраняются **исключительно** в корневой папке проекта:  
`d:/games/yandex/лайнэйдж/project-steam1/audits/`

### Структура файлов:
* `audits/README.md` — Главный реестр (индекс) всех аудитов с текущим статусом (`DRAFT`, `IN_REVIEW`, `FINALIZED`, `IMPLEMENTED`).
* `audits/[topic]_draft.md` — Первичный (начальный) черновик аудита с расчетами и выводами.
* `audits/[topic]_final.md` — Итоговый чистовой аудит в формате Markdown (с постреализационным блоком внедрения).
* `audits/[topic]_final.html` — **Стильный презентационный HTML-отчет**: автономный, адаптивный документ в премиальной стимпанк-стилистике (темный фон, медные/янтарные акценты, стилизованные таблицы, бейджи и карточки) для комфортного чтения в браузере. **Обязательно содержит блок фактической реализации и результатов тестов после внедрения в код**.

## 2. Железное Правило Единой Базы (Single Source of Truth)

> [!CAUTION]
> **Категорически запрещено** использовать внешние фантазии, приблизительные переводы ID или устаревшие markdown-документы в обход активного кода!
> В игре существует **ровно одна база правды**.

Перед составлением аудита и реализацией обязательна сверка с реальными файлами движка:
1. **Мобы и зоны**: `shared/mob-db.js` + `shared/editor-overrides.json` + `scripts/build_mobs_database_data.js`.
   * Использовать **только** каноническое поле `name` (например, *«Робот-Пылесос-Убийца»*, а не самодельный перевод «Ремонтный Дрон»).
2. **Предметы и экипировка**: `shared/item-db.js` (параметры `cDef`, `defense`, слоты `necklace`, `bracelet`, `earring`).
3. **Навыки и гейтинг**: `shared/skill-db.js` (требования к приборам `deviceReq`, слоты активации).
4. **Боевые формулы**: `shared/l2-combat.js` (C1 формулы урона, защиты, шансов блокировки и срыва каста).
5. **Экономика EXP/SP**: `shared/l2-exp-table.js` (C1 таблицы опыта и формула `spFromKill`).
6. **Квесты и диалоги**: `shared/quest-db.js` (награды, сюжетные линии).

## 3. Этапы Жизненного Цикла Аудита (Lifecycle)

```
[1. Исследование кода] ──> [2. audits/<topic>_draft.md] ──> [3. Фидбек Пользователя]
                                                                     │
[5. Удаление draft.md] <── [4. audits/<topic>_final.md + .html] <────┘
                                      │
                                      ▼
              [6. Реализация в кодовой базе & Полные Тесты]
                                      │
                                      ▼
         [7. Фиксация итогов реализации в audits/<topic>_final.html и README.md]
```

### Шаг 1. Первичный аудит (`_draft.md`)
1. Производятся все математические симуляции и расчеты через вызов вспомогательных node-скриптов.
2. Создается файл `audits/[topic]_draft.md`.
3. В отчете фиксируются:
   - Математические расчеты, формулы, EHP, TTK.
   - Сравнение с каноном Lineage 2 C1.
   - Выявленные дефекты в коде (баги расчета статов, опечатки в полях).
   - Предложения по оптимизации и балансировке.
4. Обновляется `audits/README.md` (статус: `DRAFT / IN_REVIEW`).

### Шаг 2. Обсуждение и внесение правок
1. Результаты представляются пользователю в лаконичной, структурированной форме.
2. Полученные замечания, корректировки формулировок, лора или числовых значений немедленно берутся в работу.

### Шаг 3. Финализация, HTML-отчет и очистка (`_final.md` + `_final.html`)
1. Создается файл `audits/[topic]_final.md` с выверенными данными с учётом всех правок.
2. **Генерация стильного HTML-отчета (`audits/[topic]_final.html`)**:
   - Автономный единый HTML-файл со встроенными CSS-стилями (без внешних CDN-зависимостей, работает локально).
   - Стимпанк-дизайн: темный индустриальный фон (`#0a0d12`, `#121820`), медно-латунные градиенты (`#d97706`, `#b45309`, `#f59e0b`), неоновое свечение пара (`#38bdf8`), кастомные шрифты (system-ui / Georgia), стильные таблицы с hover-эффектами, карточки боссов с бейджами уровней и тегами лута.
   - Навигационное меню (Table of Contents) для быстрого перехода по главам.
3. **Правило очистки**: Сразу после успешного сохранения и верификации `audits/[topic]_final.md` и `_final.html` черновой файл `audits/[topic]_draft.md` **безвозвратно удаляется**.
4. В папке `audits/` сохраняется идеальная чистота: остаются только актуальные финальные версии.
5. В `audits/README.md` статус меняется на `FINALIZED` со ссылками на `.md` и `.html`.

### Шаг 4. Внедрение в код и синхронизация с HTML-отчетом (`Implementation Sync`)
Когда по утвержденному аудиту пользователь инициирует реализацию («приступаем к реализации», «внедряй»):
1. **Разработка и правка кода**: Выполняются все изменения в соответствующих модулях движка (`shared/`, `server/`, `client/`).
2. **Автоматическое тестирование**: Запускаются релевантные и полные тесты (`node tests/run.js`). Проверяется 100% прохождение без регрессий.
3. **ОБЯЗАТЕЛЬНОЕ обновление HTML-отчета аудита (`audits/[topic]_final.html`)**:
   - В шапке HTML статус меняется на `badge-implemented`:
     `<span class="badge badge-implemented">Внедрено в код / Implemented & Verified</span>` (светло-изумрудный/циановый градиент с подсветкой).
   - В оглавление (Table of Contents) добавляется пункт быстрого перехода к реализации.
   - В конец HTML-документа (перед футером) добавляется полноценный интерактивный раздел:
     ```html
     <!-- Section: Implementation -->
     <section id="implementation">
       <h2>Фактическая Реализация в Кодовой Базе</h2>
       ...
     ```
   - **Содержание раздела реализации в HTML**:
     * **Карточка статуса**: Дата и время внедрения, финальный вердикт («Успешно интегрировано и верифицировано»), количество пройденных проверок.
     * **Сводка реализованных модулей**: Разделение по ключевым направлениям (Боевое ядро, Предметы, Мобы/РБ, Квесты, Диалоги, Клиентский UI).
     * **Таблица затронутых файлов**: Путь к файлу, тип изменений (изменен / создан), назначение внедренного кода.
     * **Сводка верификации и тестов**: Таблица прогона тестовых наборов с количеством пройденных ассертов (`OK: XXX пройдено, 0 провалено`).
4. **Синхронизация реестра `audits/README.md`**:
   - Статус аудита переводится в `**IMPLEMENTED**`.
   - В резюме добавляется отметка о дате завершения реализации и прохождении полного регрессионного теста.
5. **Обновление `audits/[topic]_final.md`**:
   - В конец markdown-файла добавляется секция `## Статус реализации в кодовой базе` со сводкой выполненных работ.

- [ ] Черновой файл `audits/<topic>_draft.md` удален.

- [ ] **По итогам реализации**: HTML-отчет `audits/<topic>_final.html` дополнен разделом «Фактическая Реализация в Кодовой Базе», статус обновлен на `IMPLEMENTED`.
- [ ] **По итогам реализации**: `audits/README.md` и `audits/<topic>_final.md` обновлены до статуса `IMPLEMENTED`.
