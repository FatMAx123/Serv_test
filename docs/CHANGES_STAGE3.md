# Этап 3 — изменения

## 3.1 Экипировка и заточка
- **H9 — слоты экипировки.** Слот берётся только из шаблона предмета и только из белого списка: weapon, shield, chest, legs, head, gloves, boots, necklace, bracelet, earring, title, costume (ring → bracelet). Поле `slot` из пакета клиента игнорируется. Расходники, материалы и квестовые предметы надеть нельзя (`equip_fail reason:'slot'`). В слоты title и costume попадают только предметы своего типа, в weapon — только оружие.
  - **Миграция:** при входе вещь, надетая не в свой слот, переносится в правильный слот или возвращается в сумку вместе с заточкой.
- **H10 — заточка на экземпляре.** Надетый предмет хранит свою заточку в `equip[slot].plus`, а `plusById` теперь относится только к сумке. При надевании заточка переходит из сумки на слот, при снятии — обратно.
  - **Раньше:** купленная обычная копия «делила» +N с надетой, а при выпадении после смерти +N получали обе копии.
  - **Смешивание:** держать в сумке заточенную и обычную копию одного предмета нельзя (`reason:'enchanted'`, с сообщением игроку).
  - **Обмен:** если надет +0, а в сумке +5 того же предмета, их можно поменять местами.
  - **Где обновлено:** заточка, слом, выброс, уничтожение, смерть, склад, клановый склад, обмен, лавка, магазин NPC, крафт, подбор лута.
  - **Миграция старых профилей:** «призрачная» запись `plusById` у надетой вещи удаляется.

## 3.2 /metrics и /healthz (H11)
- **/metrics:** без `METRICS_TOKEN` закрыт (403). Токен передаётся заголовком `Authorization: Bearer <METRICS_TOKEN>` или `X-Metrics-Token`. Вне production без токена доступ есть только с прямого loopback.
- **/healthz:** публично отдаёт только `{ok,status}`. Лаг, пул БД и онлайн отдаются только с токеном. Это касается и uWS fast-path, и шлюза кластера.
- **Опции:** `METRICS_PUBLIC=1` — открыть метрики явно.

## 3.3 GM по аккаунту (H5)
- **Записи по имени** в gm-access теперь хранятся как `{level, yid}`. Права действуют, только если yid совпадает, поэтому занявший имя бывшего GM прав не получает.
  - **Старые записи-числа** при старте привязываются к текущему владельцу имени. Если владельца нет, запись игнорируется (в логе будет предупреждение).
- **Выдача прав по неизвестному имени** трактуется только как выдача по yid. «Забронировать» права на имя нельзя.
- **Revoke** снимает права и с персонажа, и с аккаунта.
- **В production (или GM_STRICT=1)** флаги gm/accessLevel в профиле прав не дают. Раньше revoke не снимал GM с офлайн-игрока в Postgres.
- **Новые имена:** нельзя смешивать латиницу и кириллицу (`name_mixed`). Имя, визуально совпадающее с занятым (кириллица ≈ латиница, 0 ≈ O, 1 ≈ l), считается занятым.

## 3.4 Origin / CORS (H12)
- **Единый белый список** (`security-config.originAllowed`) для WS (обычный сервер и кластер) и CORS API. Разрешены:
  - тот же хост (Host или X-Forwarded-For-host от прокси);
  - Яндекс (yandex.ru/.net/.com/.kz/.by/.uz/.com.tr с поддоменами, включая *.games.s3.yandex.net);
  - VK;
  - 93.77.168.135;
  - адреса из `CORS_ORIGINS` (полный origin, хост или `*.domain`).
- **localhost** разрешён только вне production (или с `CORS_ALLOW_LOCALHOST=1`).
- **Убраны** пропуск `origin.includes('localhost')` (через него проходил https://localhost.evil.com), а также *.onrender.com и *.sslip.io.
- **В production проверка строгая по умолчанию.** CORS больше не отражает любой Origin.

## 3.5 Найдено при тестах: зависание больших POST через uWS
- `Buffer.from(arrayBuffer)` в мосте uWS → http создавал не копию, а вид на память, которая жива только внутри колбэка. Тело из нескольких чанков приходило неполным, и внутренний сервер вечно ждал оставшихся байтов.
- **Последствие:** сохранение реальной сцены редактора (~850 КБ) висло.
- **Исправлено:** данные копируются (HTTP-мост, шлюз кластера, WS-сообщения), Content-Length берётся по фактическому телу.

## Новые переменные окружения
| Переменная | Значение |
|---|---|
| `METRICS_TOKEN` | токен для /metrics и подробного /healthz |
| `METRICS_PUBLIC=1` | открыть метрики всем (не рекомендуется) |
| `CORS_ORIGINS` | дополнительные домены (через запятую), например `https://mygame.ru,*.mygame.ru` |
| `CORS_ALLOW_LOCALHOST=1` | разрешить localhost в production |
| `GM_STRICT=1` | строгий GM-режим вне production |
