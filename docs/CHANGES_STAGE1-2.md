# Исправления: этапы 1–2

## Новые переменные окружения
| Переменная | Назначение |
|---|---|
| `ALLOW_INSECURE_DEV=1` | Локальная разработка без YANDEX_APP_SECRET, debug_*-команды, test_*. Без него (и всегда в production) — выключено |
| `DEV_GUEST_GM=1` | (только вместе с ALLOW_INSECURE_DEV) гости local_* получают GM — как было раньше по умолчанию |
| `MOD_SECRET` (≥24 симв.) | Единственный секрет админ/мод-API. Литерал `ps-stress-perf-2026` и STRESS_SECRET больше не принимаются |
| `TRUSTED_PROXIES=ip1,ip2` / `TRUST_PROXY=1` | Кому верить в X-Real-IP / X-Forwarded-For (loopback доверен по умолчанию) |
| `STRESS_TEST=1` | Признавать префиксы стресс-ботов (они обходят античит) |
| `EDITOR_AUTO_VPS_SYNC=1` | Автосинхронизация с боевым VPS после сохранения (раньше — всегда) |
| `EDITOR_ALLOW_DEPLOY=1` | Кнопка «Деплой на Render» в редакторе |
| `PROXY_ADMIN=1`, `GAME_SERVER_PROTO=https` | Dev-прокси admin/mod API; секреты пересылаются только по https |
| `EDITOR_BACKUP_KEEP` (30) | Сколько бэкапов сцены хранить в `shared/editor-overrides.backups/` |
| `KEY_ATTEMPTS_PER_10MIN` (15) | Лимит любых попыток ввода ключа с IP |

## Этап 1 — безопасность
- `security-config.js`: единые политики (insecureDev, timing-safe сравнение, доверенные прокси).
- Гость больше не GM вне production; вход без подписи только при ALLOW_INSECURE_DEV; GM_CHARS игнорируется в prod.
- Удалён хардкод-секрет админки; IP из заголовков только от доверенного прокси.
- `move_stop`: бюджет скорости + геоклэмп + стан + хэндофф кластера (телепорт закрыт).
- `guest-auth.js`: строгий формат гостевого yid (дюп через safeName закрыт); владение аккаунтом проверяется по всем персонажам и ключу — в логине, /api/chars/*, set-codeword, codeword-status, enter-key(preferredLocalId). Новый персонаж сразу получает хэш токена.
- Перебор ключей: лимит всех попыток, code_taken считается неудачей, успех не сбрасывает счётчик.
- Редактор/dev-сервер: только валидный токен (не «любая строка ≥16»), loopback без прокси-заголовков, сессия генерирует свой токен, SameSite=Strict, CORS `*` убран, VPS-синк и деплой — по opt-in, прокси без утечки секретов.
- revokegm / понижение уровня отзывает editor-токен; set_time больше не доступен по editorKey.
- WS `save_editor_data` запрещён при выключенном редакторе (production).

## Этап 2 — редактор
- Сервер: проверить → атомарно записать → применить в runtime → инвалидировать коллизии → разослать `editor_overrides_updated`.
- Writer: whitelist схемы, ревизия `rev` + `baseRev` (409 при конфликте), недостающие ключи берутся с диска, weaponGrips сливаются, защита от вайпа для всех массивов мира, tmp+rename, ротация бэкапов, свежий savedAt.
- `editor-overrides-data.js` отдаётся с `no-cache`+ETag — игроки получают новую версию при перезаходе.
- Клиент: одна запись в полёте + слияние вызовов, успех только по ответу сервера (HTTP или WS ack с reqId), конфликт/вайп — диалог, ретраи с backoff, индикатор «Не сохранено», предупреждение при закрытии вкладки, автосохранение любых правок (включая drag) через 1.5 с.
- Покраска террейна: ошибка сервера больше не считается успехом; отправляется только при изменениях.
- world-metrics: инвалидация коллизий после смены пропсов, снятие `_deleted` у спотов, ветер из переданного снапшота.
- Деплой из редактора — только после подтверждённого сохранения.

## Важно при выкладке
1. Прод: `NODE_ENV=production`, задать `MOD_SECRET`, `YANDEX_APP_SECRET`; проверить `gm-access.json` на лишних GM (раньше любой гость мог выдать себе права через //setgm).
2. Локально для прежнего поведения: `ALLOW_INSECURE_DEV=1 DEV_GUEST_GM=1`.
3. Гостевые аккаунты с не-каноничным id (заглавные буквы, точки и т.п.) больше не войдут — штатный клиент такие id не создаёт.
4. Если перед сервером стоит nginx/CDN с собственным кэшем статики — исключить `js/editor-overrides-data.js`.

## Этап 2.5 — проверка в production (uWebSockets.js + PostgreSQL) и найденные при этом баги
Прогон с `NODE_ENV=production`, uWS, PostgreSQL 15: `tests/smoke-prod.js` — 17 проверок.
Исправлено:
- **Подмена IP через HTTP-мост uWS** (`net-transport.js _proxyHttpRequest`): заголовок `X-Real-IP` клиента сохранялся,
  а внутренний http-сервер доверял loopback → все HTTP rate-limit обходились. Теперь мост всегда перезаписывает заголовки.
- **Гонка старта на Postgres**: реестры (ключи, GM, персонажи, кланы) читались до создания схемы → на чистой БД
  `relation "system_state" does not exist`. Теперь загрузка ждёт `DB.init()`.
- **Затирание реестра ключей**: при ошибке чтения/расшифровки (сбой БД, неверный `KEY_VAULT_SECRET`) реестр оставался
  пустым, и первая же регистрация ключа перезаписывала его — все игроки теряли ключи. Теперь запись блокируется,
  `enter-key`/`set-codeword` отвечают `busy`, при сбое БД — повторная загрузка каждые 10 с. Аналогично для `gm_access`.
- **Профиль с ключом `undefined`**: `saveProfileNow(pr)` вызывался с профилем вместо игрока → в БД появлялась строка
  `yid='undefined'` с данными последнего вошедшего гостя.
